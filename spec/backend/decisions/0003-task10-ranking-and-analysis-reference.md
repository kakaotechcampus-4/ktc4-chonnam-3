# 0003 Task 10 후보 순위와 run별 L1 참조

- 상태: Proposed — 구현 적용, 팀 리뷰 대기
- 날짜: 2026-09-28
- 관련 PR: 이 문서를 포함하는 Task 10 PR; 선행 #45, #73, #75, #79.
- 검토자: 팀 리뷰 대기

## 맥락

후보 선택에는 이미 `pushed_at` 순서와 첫 배치 3+5+2 규칙이 있다. 숫자 JD 적합도는
[AI 0017](../../ai/decisions/0017-recommendation-score-deferral.md)에서 보류했고,
[AI 0018](../../ai/decisions/0018-existing-baseline-bulk-resolution.md)은 기존 후보 순서를 유지한다.
`repo_analyses`는 저장소·분석 단계·SHA·프롬프트 버전으로 유일하며 run FK가 없다.
실패한 캐시를 재시도하더라도 과거 run의 실패를 다른 run의 성공으로 바꾸면 안 된다.

## 결정과 이유

- 기본 순서는 `pushed_at DESC NULLS LAST`, 동률은 `github_repo_id ASC`로 고정한다.
  `ranking_score`는 `100 × (후보 수 - base_rank + 1) / 후보 수`를 소수 셋째 자리까지
  저장하는 순위 표시값이다. 새로운 가중치나 JD 신호를 넣지 않으며 추천 정렬에 사용하지 않는다.
- `ranking_signals`에 순위 정책, 최근 push 시각, 포트폴리오 언급·기본 필터 통과 여부를 남긴다.
  `candidateSource`는 배치 슬롯 이름이 아니라 언급·필터의 두 근거로 결정한다.
- 기여도 슬롯은 호출자가 이번 요청에서 확인한 `RepoDetail` 중 현재 저장된 SHA·사용자 커밋 수와
  일치하는 자료만 사용한다. 자료가 없으면 슬롯을 비운다. 목록 수집의 `synced_at`을 상세 자료의
  신선도 증거로 쓰거나 stars/forks를 개인 기여로 바꾸지 않는다.
- 같은 JSON의 `analysis` 키에 해당 후보에서 확정한 `analysis_id`, `head_sha`, `prompt_version`,
  `status`, `error_code`를 둔다. L0-b에서 중단된 경우에는 분석 ID가 없을 수 있다.
  성공 L1 참조는 ID·저장소·단계·SHA·버전·상태를 모두 대조한다. 최신 행을 임의로 고르지 않는다.
- 실패 캐시는 재시도 결과로 갱신할 수 있으나 이미 성공한 캐시는 늦은 실패로 덮어쓰지 않는다.
  이전 후보의 상태 snapshot을 유지하므로 과거 실패·부분 결과는 이후 캐시 성공과 구분된다.
- 후보 분석 참조가 바뀌면 같은 run 잠금 아래 기존 추천을 무효화한다. 추천 단계는 전체 후보를
  `base_rank` 순서로 다시 계산해 모든 페이지 합산 최대 5개를 저장한다.
  카드 조회는 run 공유 잠금으로 여러 SELECT 사이의 분석·추천 교체를 막는다.

## 영향과 경계

기존 테이블·JSONB·nullable score를 사용하며 새 마이그레이션이나 공개 API 필드는 없다.
JSON은 추천 근거와 run별 분석 참조를 함께 담으므로 다른 단계가 모르는 키를 덮어쓰지 않는다.
수치 `matchScore`는 항상 null이다. 추천과 사용자의 직접 선택은 별개이며 선택 필드를 추가하지 않는다.
Task 11은 내부 함수 호출 전 소유권·만료·페이지 상태를 확인하고, 분석 후 추천 재계산까지 끝난 뒤
페이지 완료를 표시해야 한다. 카드 조회의 읽기 트랜잭션도 응답 조립 직후 종료한다.

대체 관계: 기존 AI 0017/0018과 첫 배치 정책을 유지하는 내부 저장·동시성 보완이다.
후보의 분석 참조를 별도 컬럼으로 옮기게 되면 JSON 기존 참조의 이관을 먼저 마련한다.
