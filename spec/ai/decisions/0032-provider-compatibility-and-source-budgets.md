# 0032 실제 공급자 호환과 원문 수집 예산 경계

- 상태: Proposed — 사용자 요청에 따른 로컬 호환 보완. 공유 계약·운영 설정의 팀 승인을 대신하지 않는다.
- 날짜: 2026-11-07
- 관련: [0031](0031-final-service-runtime-boundaries.md), [#196](https://github.com/kakaotechcampus-4/ktc4-chonnam-3/issues/196)
- 구현·실행 결과: [단일 구현 기록](../implementation.md#live-ai-validation-20261107)

## 맥락

공급자 주소·키가 존재해도 설정명, URL 접미사, 요청 헤더, 원문 위치 필드와 실행 예산이
실제 서비스의 형식에 맞지 않으면 기존 AI 기능에 연결되지 않는다. 수집에 성공한 자료와
확인하지 못한 자료, 호출 설정과 모델 자체의 능력을 구분할 필요가 있다.

## 결정

1. GitHub의 앱 식별 `User-Agent`는 일반 조회와 직접 생성한 원문 요청이 같은 상수를 사용한다.
   구조 목록의 디렉터리 표시는 끝의 `/` 한 개를 허용하되, 파일 Evidence의 경로 검증은 유지한다.
   절대 경로·상대 이동·중복 구분자를 허용하는 예외로 확대하지 않는다.
2. 구조 탐색과 파일 원문 수집은 전체 요청·바이트 예산을 공유한다. 구조 탐색이 전부 소진하지 않도록
   선택 가능한 파일 수와 실제 reader 응답 상한에 근거해 원문 조회 몫을 남긴다.
   전체 예산보다 많이 예약하지 않고, 구조·원문 중 미확인 범위는 결과의 한계로 유지한다.
3. Vision은 명시적인 `VISION_BASE_URL`·`VISION_API_KEY`를 우선한다.
   기존 `Helpy_Vision_Document_PROXY_URL`만 사용하는 연결에는 공통 `PROXY_TOKEN`을 재사용할 수 있다.
   명시한 다른 Vision 주소에 공통 토큰을 암묵적으로 전달하지 않는다.
   `/v1` 접미사는 어댑터의 문서 API 경로와 중복하지 않도록 정규화하고 프록시 namespace는 보존한다.
4. Vision의 기존 `coordinate`를 우선하고, 없는 경우 실제 `bounding_box`를 위치로 보존한다.
   원본 공급자 결과와 원문·파일 해시를 유지하며, 좌표 보완을 텍스트 재작성으로 처리하지 않는다.
   OCR 전사와 생성된 도식 설명, 부분 인식 한계는 계속 구분한다.
5. 공급자의 출력 제한은 해당 endpoint·모델·스트리밍 여부·실제 요청 설정으로 확인한다.
   비스트리밍 제한을 모델 전체의 context 또는 보편적 출력 한도로 일반화하지 않는다.
   검증용 override는 운영 기본값·작업별 품질 정책과 구분하며 원본 설정을 조용히 변경하지 않는다.
6. 후보 검수의 거절은 성공 질문으로 저장하거나 완주로 계산하지 않는다. 검증 도구에서 별도 작업을
   시작하더라도 원 실패를 보존하고 서비스 자동 복구로 표시하지 않는다.
   이 결정으로 의미 검증 실패의 자동 재시도나 기존 논리 작업의 호출 상한 확대를 승인하지 않는다.

## 영향과 한계

외부 연결에 필요한 호환 보완이며 새로운 FE 응답 필드나 자율 분석 Agent를 제안하지 않는다.
실제 기능 검증·합성 입력 검사·통계적인 품질 평가·전체 서비스 완주를 별개로 보고한다.
STT의 기존 설정명 호환과 TTS는 별도 확인 범위로 남긴다.
