## 목적과 기존 구조

반복해서 면접에 사용한 저장소나 코드량이 큰 저장소 때문에 프로필 언어 비율이 치우치지 않도록 한다. 기존 저장소별 언어 비율을 재사용하며 코드량에 따른 가중치를 새로 계산하지 않는다.

[0015](0015-existing-contracts-and-tool-results.md)의 `profile_summary(user_id)`, `user_profile_summaries`, 공개 필드 `basedOnRepoCount`, `languages`, `projectTypes`, `roleSummary`를 유지한다. [0006](0006-task-llm-usage-policy.md)의 Sprint 1 LLM 비호출과 기존 report 성공 후 갱신·실패 분리 정책도 유지한다.

## 집계 기준

1. 해당 사용자의 완료된 면접에 사용된 저장소만 대상으로 한다. 전체 수집 목록이나 완료되지 않은 면접만의 저장소는 포함하지 않는다.
2. 기존 저장소 식별자로 중복을 제거한다. 같은 저장소를 여러 면접 또는 다른 ref로 사용해도 한 번만 센다. `basedOnRepoCount`는 이 서로 다른 저장소 수다.
3. 각 저장소의 기존 유효한 언어 비율에 동일한 비중을 준다. 언어별 최종 비율은 해당 언어의 저장소별 비율 합계를 대상 저장소 수로 나눈 값이다. 코드량·면접 횟수·ref 수로 가중하지 않는다.
4. 유효한 언어 분포 안에 특정 언어가 없으면 해당 언어의 기여는 0이다. 그 언어를 사용하는 저장소만으로 분모를 줄이지 않는다.

예를 들어 저장소 A가 Python 100%, B가 Java 100%이면 프로필은 각각 50%다. A를 세 번 면접에 사용해도 50%씩이며, A의 코드량이 더 커도 같다. A가 Python 80%·JavaScript 20%, B가 JavaScript 100%이면 Python 40%·JavaScript 60%다.

대상 저장소 전체의 언어 자료가 갖춰져야 이 평균을 확정할 수 있다. 어느 저장소의 언어 자료 자체가 없거나 유효하지 않은 경우는 특정 언어의 0%와 다르다. 0으로 채우거나 해당 저장소를 조용히 제외해 성공 결과로 저장하지 않고, 기존 갱신 실패 경계에서 직전 성공 요약을 유지한다. 이미 성공한 리포트에는 영향을 주지 않으며 자동 재시도·새 복구 흐름을 추가하지 않는다.

## 자료 재사용과 변경 범위

기존 L0-b는 languages와 head_sha를 수집하고 기존 공개 `LanguageRatio`는 name·ratio를 사용한다. 집계는 기존에 저장한 저장소별 언어 자료를 재사용한다. 프로필 계산만을 위한 추가 GitHub 조회·코드량 수집·과거 ref 복원·새 스냅샷 테이블은 요구하지 않는다.

현재 명세만으로 언어 통계가 모든 면접 당시 ref별로 영구 보존된다고 볼 수는 없다. 이 결정은 언어 통계를 당시 면접의 코드 스냅샷과 동일한 시점의 값으로 보장하거나 최신 완료 면접의 자료를 선택하는 별도 정책을 만들지 않는다. 실제 저장 필드·참조 키·자료 유효성 검사는 기존 수집·저장 경계에 맞춰 구현 시 확인한다. 기존 자료만으로 연결되지 않는 문제가 확인되면 그 실제 영향만 검토한다.

DB 테이블·컬럼과 공개 API 형식을 바꾸지 않고 집계 로직을 구체화하는 결정이다. 코드·migration·실제 집계 구현이 완료됐다는 뜻은 아니다.

## Sprint 1 개인 역할 요약

2026-09-22 후속 사용자 선택에 따라 개인 역할 요약 생성을 보류한다. 프로필 응답의 기존 `roleSummary` 문자열에는 **“개인 역할 요약은 아직 제공하지 않습니다.”**를 사용한다. 이는 기능 제공 범위에 대한 안내이며 사용자의 역할이 없거나 확인되지 않았다는 평가가 아니다.

- 기존 프로필 패널과 문자열 필드를 그대로 사용한다. 새 필드·상태·컬럼·입력 화면을 추가하지 않는다. `analysis`가 null인 기존 홈 상태도 유지한다.
- README·commit·프로젝트 기능 요약으로 개인 기여를 추정하지 않는다. 면접 발언에서 역할을 골라 새 요약을 만드는 처리와 추가 LLM 호출도 Sprint 1에 도입하지 않는다.
- 언어 비율·프로젝트 유형 집계, report 후 갱신과 실패 독립 흐름은 유지한다. 역할 요약을 보류한다는 이유로 프로필 전체를 실패시키지 않는다.
- 기존 예시나 저장 자료의 추정 역할 문장을 Sprint 1 응답에 그대로 노출하지 않는다. 이 안내를 위해 기존 면접 답변·분석 원문이나 과거 기록을 일괄 변경하지 않는다. 저장·응답 변환의 상세 연결은 기존 필드 안에서 구현 시 정리한다.
- 실제 개인 역할 요약 도입은 후속 기능 검토 때 출처·표현·처리 범위를 함께 정한다. 기존 자료만으로 검증된 개인 역할 요약이 구현됐다고 보지 않는다.

## 검증과 남은 범위

- 같은 저장소를 여러 면접·ref에서 사용해도 한 번만 집계한다.
- 위 50/50 및 40/60 예시와 코드량·면접 횟수에 따른 가중치가 없음을 확인한다.
- 특정 언어의 부재와 저장소 전체 언어 자료 누락을 구분한다. 누락 때문에 잘못 계산한 새 요약으로 직전 성공 요약을 덮어쓰지 않는다.
- 기존 공개 필드·타입, report 후 enqueue, LLM 비호출과 실패 독립을 유지한다.
- 프로필이 있는 응답의 `roleSummary`가 위 안내 문자열이며 개인 기여 추정·발언 요약·추가 LLM 호출이 없는지 확인한다. 프로필이 없는 기존 홈 상태는 그대로다.

언어 집계 확정 뒤 남았던 역할 요약 내용까지 정했으므로 AI-L17을 의사결정 대기 목록에서 해소한다. 상세 저장 매핑·job·응답·화면 검증은 채택한 의미와 기존 구조 안에서 구현 시 수행하며 구현 완료로 표시하지 않는다. L1 프로젝트 기능 요약의 저장 매핑은 별도 AI-L03 범위로 유지한다.
