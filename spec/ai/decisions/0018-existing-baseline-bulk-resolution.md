- 상태: Accepted — 아래 명시한 기존안 채택과 검토 방식
- 날짜: 2026-09-22
- 결정자: 현재 사용자
- 관련 PR: 없음
- 근거 지시: “기존안으로 해서 정할 수 있는 건 그대로 정해서 넘기고 꼭 질문이 필요한 것들만 질문해.”
- 후속 사용자 선택: 이번 Sprint 1은 **팀 내부 검증, 실제 사용자 문답 사용** 범위다.
- 후속 자료 선택: 실제 문답과 연결된 분석·리포트·실패 기록을 **후속 내부 비교 검증에도 보관·재사용하는 2번 안**을 채택한다. **현재 프로젝트의 최종 내부 비교 검증이 끝난 뒤에도 보관하며, 별도의 자동 삭제 기한은 두지 않는다.**

## 목적과 범위

[0014](0014-minimal-change-revision.md)의 최소 변경 기준에 따라 기존 명세·코드를 대조하고, 남아 있던 22개 주제를 다시 개별 선택 질문으로 만들지 않는다. 이 결정은 기존안을 유지하는 설계 정리이며 코드·DB migration·실제 호출·검수·출시 완료가 아니다.

현재 Sprint 1 범위에서 추가 사용자 선택이 필요한 항목은 없다. 확정한 방향과 후속 결정은 [AI 결정 기록](README.md), 결정된 방향을 구현·검증할 작업은 [AI 작업 지도](../../../ai/docs/pipeline.md#기존-id별-구현검수-인계), Sprint 2의 미정 세부는 [후속 검토 목록](../features/extensions.md#sprint-2-착수-시-검토할-사항)에서 관리한다. 항목 이동을 결정·구현 완료로 해석하지 않는다.

## AI-L07 추천의 기존안 채택

[기존 match_score 골격](../../../backend/app/features/analysis/pipeline/steps/match_score.py)의 공고 기술 태그와 유효한 L1 기술 목록 직접 비교를 사용한다. 추가 숫자 점수·의미 순위 모델·새 LLM 호출은 만들지 않는다.

1. 공고의 기술 목록과 저장소 분석에서 확인한 기술이 직접 일치하면 추천 관련 근거로 사용한다. 기술 정보가 없거나 일치가 없으면 정상 미추천이며 사용자 직접 선택은 유지한다. 이를 분석 실패나 낮은 적합도 판정으로 바꾸지 않는다.
2. 추천 근거가 있는 후보를 기존 run 후보 순서에서 최대 5개 선택한다. 비동기 분석 완료 순서로 순위를 바꾸지 않는다. 상한은 페이지마다가 아니라 run 전체다. 순서를 JD 적합도 순위라고 설명하지 않으며 사용자 확정 선택을 임의로 바꾸지 않는다.
3. 이유는 일치한 기술의 관련성만 설명한다. “Python 3년 경험”과 Python 저장소의 연결이 경력·자격 충족을 뜻하지 않는다.
4. 공고 전체 기술 태그가 모든 요구사항 행에 복사된 기존 구조를 고려한다. 개별 요구사항 ID는 해당 문장에서도 그 기술이 명시적으로 확인될 때만 연결하고, 그런 근거가 없으면 빈 목록으로 둔다. 모든 요구사항 ID를 태그 겹침만으로 연결하지 않는다.
5. [0017](0017-recommendation-score-deferral.md)의 필수 `matchScore=null`, 기존 카드·추천 이유·선택 상한·7개 분석 단계·저장 위치를 유지한다.

이 범위로 AI-L07의 별도 사용자 선택은 해소한다. 직접 일치 판정·중복 제거·정렬 키·저장·응답 연결의 세부는 기존 생산자·소비자에 맞춰 구현하고 검증한다.

## 운영 범위와 남은 구현·검증

사용자가 이번 범위를 팀 내부의 실제 사용자 문답 검증으로 선택했다. 외부 서비스 출시·대규모 동시 운영을 현재 전제로 두지 않고 내부 대표 사례의 품질·실패·시간·비용을 확인한다. 실제 자료는 아래 후속 선택에 따라 내부 비교 검증에도 보관·재사용하고 최종 내부 비교 검증이 끝난 뒤에도 보관한다.

LLM·Tool·job의 timeout·token·동시성 수치는 현재 골격에 없다. Wanted HTTP의 기존 10초나 면접 시간·사용자별 면접 제한을 다른 실행 상한으로 복사하지 않는다. 내부 검증의 대표 입력과 계정 한도에 맞춰 유한한 실행 설정·비용 범위를 먼저 정하고 측정으로 조정한다. 사용자가 지정한 한도가 있으면 그 한도를 우선하며 미설정 무제한 실행을 허용하지 않는다. 세부 수치를 하나씩 선택하게 하지 않고 구현·측정 계획에서 묶어 정리한다. 실제 검수 결과·표본 수·품질 수치를 만들어 기록하지 않으며 외부 출시 수용 기준은 외부 운영 검토 시 확인한다.

실제 사용자 문답과 모델 실패 원문의 기존 보존 요구를 유지하며 이번 선택에서는 별도의 자동 삭제 기한을 두지 않는다. 기존 저장 구조에서 충족할 위치·권한·보관 방식을 확인하기 전 운영 저장 구현이 완료됐다고 하지 않는다.

사용 대상·후속 내부 재사용·보관 유지 방향은 확정했다. 현재 범위에서 추가 사용자 선택이 필요한 항목은 없다. 상세 저장 위치·필드·설정·검수 절차는 채택한 범위에 맞춰 구현 시 확인하며 Sprint 2의 미정 세부는 해당 기능 착수 시 검토한다.

## AI-L18 후속 내부 비교 검증 자료

2026-09-22 사용자가 2번 안을 선택한 뒤 종료 시 삭제에 동의했으나, 이어서 “아니다. 보관하는 걸로 하자.”라고 정정했다. 최신 선택에 따라 삭제 결정은 철회하고 문답·연결 분석·리포트·실패 기록을 최종 내부 비교 검증이 끝난 뒤에도 보관한다.

- 목적은 현재 프로젝트의 채택된 기능·설정·프롬프트에 대한 품질·실패·회귀 비교다. 필요한 팀 검수자만 접근하고 참여자에게 이 후속 사용 범위를 알리며 실제 자료의 사용 권한·동의를 확인한다.
- 팀 내부 사용은 자료의 검수·공유 목적 범위다. 이미 선택한 모델 API로 기존 task를 실행하는 흐름은 유지한다. 외부 공개·별도 배포·모델 추가학습의 승인을 뜻하지 않는다.
- 문답·최초 분석·당시 근거와 비교 결과를 구분해 기존 보존 의미를 유지한다. 기존 source group 분리·평가 정답 격리·최종검증 자료의 재사용 시 회귀자료 분류도 유지한다.
- 실제 자료의 저장·마스킹·권한·복사본·파생 분석·리포트 관리는 기존 구조 안에서 구현·검증한다. 합성 fixture용 경로를 실제 사용자 자료의 공개·배포 경로로 사용하지 않는다. 이 선택만으로 새 테이블·저장소·관리 화면을 추가하지 않는다.
- **최종 내부 비교 검증 종료 뒤에도 보관하며, 별도의 자동 삭제 기한은 두지 않는다.** 비교용 복사본·파생 자료에도 같은 사용 목적·접근 범위를 적용한다. 기존에 별도로 정한 삭제 동작이 있다면 이를 임의로 제거하지 않으며, 이번 보관 선택을 자료 사용 목적이나 접근 대상의 확대로 해석하지 않는다.

이번 작업은 문서상의 정책 선택 반영이며 실제 자료를 수집·이동·재사용·삭제한 것은 아니다.

## 확인 기준

- 기존 계약·테이블·단계·job·정상/실패 의미를 새 구조로 바꾸지 않았는지 확인한다.
- 추천의 직접 기술 일치·미추천·실제 요구사항 연결·run 전체 최대 5개·숫자 미계산을 구현 시 검사한다.
- 구현 인계·자료 검수·미래 결정으로 옮긴 항목의 ID·원래 미정 범위를 보존한다.
- 문서·링크 검사를 코드 동작·실제 모델 품질·저장/복구 검증으로 보고하지 않는다.
