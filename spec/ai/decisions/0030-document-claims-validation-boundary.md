## 맥락

0029의 AI 모듈 승인과 서비스 연결 준비는 별개다. `interview_turns.claim_ids`와 답변의 `claim_checks`가 있다는 사실만으로 문서 Claim의 면접 소비 계약이 완성되지는 않는다. 또 항목별 schema·줄 ID를 번갈아 검사하면 같은 혼합 오류도 항목 순서에 따라 재시도 여부가 달라진다.

## 결정

1. **검증 순서**: 응답 전체와 모든 Claim의 schema를 먼저 검사한다. 모두 통과한 뒤 이번 요청의 줄 ID인지 검사한다. 혼합 오류는 항목 순서와 무관하게 schema 실패이며 공통 재시도 정책을 따른다. schema가 맞지만 없는 ID를 참조하면 semantic 실패로 재시도하지 않는다. 한 항목 위반 시 전체 거절과 정상 빈 목록의 성공은 유지한다.
2. **추출 보장 범위**: 줄 ID는 입력한 저장 `extracted_text`의 빈 줄 제외 0번 시작 순번이다. 두 줄에 걸친 주장은 시작 줄과 해당 한 줄 원문만 복원한다. 원본 페이지·문단·전체 source span을 뜻하지 않는다. ID 존재 검사는 한국어 작성·기술과 수치 보존·중복 제거·주장의 진위를 검증하지 않는다. 언어·기술과 수치 보존·중복 등 추출 충실성은 prompt 지침과 별도 품질 평가로 확인한다. 주장의 사실 여부 판정은 추출 범위 밖으로 유지한다.
3. **면접 소비 경계**: 문서 Claim을 전달할 `Context`, 문서용 `BasisKind`, 질문의 `claim_ids` 연결과 문서·답변 주장 구분을 후속 계약으로 확인한다. 기존 `claim_checks.claim_text`는 현재 `answer_text`의 실제 인용이어야 한다. 문서 문장을 곧바로 넣거나 기존 답변 인용 검증을 완화해 우회하지 않는다.
4. **승인 범위**: 0029의 Accepted는 독립 AI 추출 설계의 채택으로 읽는다. 내부 모듈 추가로 Sprint 1 Claim 생성·저장·면접 활용을 활성화하지 않는다. 사용자 확인 화면을 추가하지 않는 모듈 범위와, 서비스에서 사용자 확인 없이 질문에 활용하는 정책의 협의는 구분한다.

## 서비스 연결 조건과 책임

- BE는 실제 호출 위치·prompt 등록·adapter·저장·문서 권한·결과 보존을 확인한다. 저장된 문서와 입력 텍스트 버전을 결합하고 동일한 비빈줄 순번으로 원문을 복원한다. 재추출·축약·정규화로 텍스트가 달라지면 이전 번호를 재사용하지 않는다.
- 0029의 "같은 문서 row는 한 번"은 문서·추출 텍스트 버전을 식별해 결과를 재사용하는 방향이다. 분석 run마다 새로 호출한다는 뜻이 아니다. 동일 문서·버전의 미실행·처리 중·정상 빈 결과·실패를 구분하고 동시 호출·재시도 정책을 정해야 한다. Claim row 0개만으로 재호출을 결정하지 않는다.
- 비용의 최대 2회는 단일 추출 작업의 공통 호출 계층 시도 상한이다. 문서 버전 변경·실패 후 재실행의 허용과 중복 방지는 BE가 별도로 정한다. `documents_max_text_chars`의 50,000자는 preview 설정의 기본값이며 이 AI 함수의 자체 문자 상한이 아니다. 입력 줄 ID 포장 후의 Gateway byte budget도 확인한다.
- 알려진 모델 실패는 실패 정보·시도 기록과 빈 Claim으로 반환한다. BE는 이를 영구 기록하고 선택적 Claim 없이 분석을 계속하는 정책을 연결한다. 프로그래밍 오류·취소·DB 오류까지 빈 결과로 바꾸는 정책은 채택하지 않는다. 면접 이전 호출 기록은 면접 ID가 필수인 기존 `LLMCallRecord`의 직접 재사용을 가정하지 않고 저장 위치를 정한다.
- Director·면접 담당은 문서 Claim의 권한·근거 종류·질문 연결과 기존 답변 주장 검증의 구분을 확인한다. 문서·코드 충돌의 source·FK·보존과 사용자 확인·수정·제외 정책은 관련 담당자가 함께 검토한다.

## 이유와 영향

전체 schema를 먼저 검사하면 오류 분류·재시도 여부가 모델의 항목 순서에 좌우되지 않는다. 기존 정상 출력, 4종·20개·태그 5개 제한, task·prompt·schema version과 전체 거절 정책은 유지한다. 공개 API·DB schema·FE 화면·BE 실행 순서는 바꾸지 않는다. 검증 결과와 실제 연결 현황은 구현 기록 한 곳에 둔다.

## 대체 관계

0029의 내부 추출 설계와 원본 기록은 보존한다. 이 결정은 혼합 오류 우선순위를 보완하고, 맥락의 "면접 쪽은 준비되어 추출만 빠짐", 결정 6의 기존 `claim_checks` 직접 활용, 영향의 문서당 1회·run당 비용·50,000자 설명을 위 경계로 정정한다. 서비스 연결·사용자 확인에 관한 다른 담당자의 합의를 새로 확정하지 않는다.
