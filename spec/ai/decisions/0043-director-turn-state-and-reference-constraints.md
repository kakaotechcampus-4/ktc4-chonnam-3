# 0043 — Director의 턴 상태와 실제 참조 식별자 제약

상태: Accepted for local development, 2026-11-09.
사용자가 요청한 Luna 개발 기본 방향과 Sol/Luna의 같은 조건 비교에 적용한다.
질문·평가 내용의 사람 검수나 공개 서비스 운영 승인을 대신하지 않는다.

## 맥락

다음 질문을 생성하는 시점의 질문 번호와 이미 답변이 끝난 문답 수는 다르다.
예를 들어 8개 답변을 확정한 뒤 생성하는 질문은 9번이며, 마지막 답변은 아직 받지 않았다.
모델이 두 수를 같은 뜻으로 해석하면 허용된 마지막 질문을 거절할 수 있다.
또한 자유 문자열로 근거 ID를 다시 작성하면 원문을 올바르게 이해해도 ID 오타로 검증에 실패할 수 있다.
이 문제를 해결하면서 서버의 종료 권한과 원문·참조 검증은 유지해야 한다.

## 결정

- Controller가 확정한 문답 이력으로 모델 입력의 `turn_state`를 계산한다.
  `next_question_no`는 지금 생성·검토할 질문 번호이고, `answered_turn_count`는 답변을 확정한 문답 수다.
  직전 답변의 번호·ID, 전체 질문 수, 남은 질문 수와 마지막 질문 여부도 별도로 전달한다.
- 질문 번호는 답변 수에 1을 더한 값이어야 하며, 직전 답변 ID와 페르소나별 답변 수가
  실제 이력과 일치하는지 코드가 먼저 검사한다. 모델이 이 상태를 다시 정하지 않는다.
- `is_final_question=true`는 마지막 질문의 생성·검토 단계라는 뜻이다.
  종료 권한은 마지막 답변을 받은 Controller에 있으며, 질문 번호만으로 조기 종료하지 않는다.
- `director_v6`의 Plan schema는 실제 입력에 등록된 근거 종류별 ID, Evidence ID,
  JD 요구사항 ID, 과거 문답의 parent ID와 현재 허용된 페르소나를 enum으로 제한한다.
  모델은 허용된 식별자를 그대로 선택하며, 없는 식별자는 선택 후보에 넣지 않는다.
- enum은 현재 제공한 자료의 참조 가능 범위다. 분석의 정답이나 읽을 파일명을 고정하는 규칙이 아니다.
  단일 Director와 기존 Tool 구조, 서로 다른 레포의 실제 구조에 따른 자료 선정 원칙을 유지한다.
- 출력 후의 기존 schema·semantic 검증도 유지한다. ID 자동 보정·추정·근접 문자열 매칭이나
  검증을 통과시키기 위한 의미 조건 완화는 하지 않는다.
- 리포트에서 과거 답변 분석을 검증할 때도 면접에 저장한 조회 후보의 승인 범위를 복원한다.
  소유한 선택 레포와 고정 SHA가 일치하는 snapshot만 공통 경로 검증기로 읽는다.
  조회 후보는 추가 확인을 요청할 수 있는 경로이며, 읽은 원문·Evidence·Tool 성공 결과가 아니다.
  리포트 복원을 위해 현재 HEAD나 새 파일 목록을 가져오거나 과거 분석·원응답을 덮어쓰지 않는다.
- Plan 1회와 독립 Review 1회의 기존 총 2시도 예산을 유지한다.
  잘못된 참조에 대한 semantic 실패를 숨은 추가 모델 호출로 해결하지 않는다.
- 새 프롬프트와 Plan schema 버전을 사용하고 기존 v4·v5 본문과 과거 저장 결과는 보존한다.
  `turn_state`는 v5·v6 모델 입력의 내부 투영이며 공개 API와 기존 `Context` dataclass를 확장하지 않는다.
- 로컬 개발 연결의 기본 방향은 Luna slot 1로 두고 Sol slot 3 연결도 보존한다.
  실제 서비스 task는 활성 DB `PromptVersion`의 모델을 사용하므로, 모델 전환에는 새 deployment로
  등록한 프롬프트의 모델·본문·버전과 선택한 연결 슬롯의 모델이 일치해야 한다.
  환경 파일의 슬롯만 바꾸거나 기존 분석 결과의 모델 표시만 바꾸어 전환한 것으로 보지 않는다.

## 이유와 영향

턴의 의미를 코드에서 계산하면 같은 이력을 모델이 다시 집계하거나 종료 조건으로 오해할 여지를 줄인다.
실제 ID의 선택 범위를 출력 schema에도 전달하면 원문·소유권 검증을 생략하지 않고 참조 오타를 예방할 수 있다.
원문 누락, 근거 없는 주장, 부적절한 질문 내용까지 enum이 해결한다고 보장하지 않는다.

내부 모델 입력과 버전별 Plan schema, 로컬 개발 연결 설정에 영향이 있다.
FE·BE 공개 요청·응답 계약과 Controller의 최종 답변 이후 종료 순서는 유지한다.
두 모델의 비교는 같은 제품 코드·프롬프트·원문·후보 응답 정책·예산에서 새 DB와 캐시로 실행한다.
조건을 바꾼 재검증은 최초 실행과 분리하고 이전 실패·호출 비용·미확인 범위를 보존한다.

0038·0040의 유한 예산·단일 Director·원문 보존 경계를 구체화한다.
실제 구현 위치·검증 수치·실패와 재검증 상태는 [구현 기록](../implementation.md)에만 남긴다.
