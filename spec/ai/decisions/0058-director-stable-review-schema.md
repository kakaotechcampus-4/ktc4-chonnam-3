# 0058 Director 필수점 검토의 고정 응답 스키마

상태: 2026-11-11 로컬 실험 개발·평가 채택.

## 맥락

필수점별 검토는 질문에 없는 요구를 채점 조건으로 승인하는 문제를 확인하기 위한
장치다. v14/v15는 질문별 필수점 이름을 JSON Schema의 속성 이름으로 사용한다.
따라서 질문이 달라지면 검토 정책이 같아도 응답 스키마가 바뀐다. 생성·검토 시간과
사용량을 줄일 방법을 검토하되 필수점별 검증과 독립 검토를 유지해야 한다.

## 결정

- v16의 사적 모델 응답은 `director-review.v3`를 사용한다. 다섯 boolean과 짧은 사유를
  유지하고 `point_coverage`를 `{key, status, question_excerpt}`의 배열로 받는다.
- 배열 원소의 스키마에 후보별 키·개수 제한을 넣지 않는다. 실제 후보의 필수점 키
  집합과 정확히 일치하는지, 중복·누락·미등록 키가 있는지는 실행 코드에서 검사한다.
- `asked`에는 실제 질문의 비어 있지 않은 연속 원문 인용이 필요하다. 다른 세 상태의
  의미와 반려·복구 규칙은 [0056](0056-director-required-point-review.md)을 유지한다.
  형식 오류나 미포함 필수점을 승인한 결과는 저장 가능한 질문으로 바꾸지 않는다.
- 실행·저장 시도 복원·사적 진단은 같은 버전 선택기와 판정기를 사용한다. v1/v2와
  기존 배포 버전의 요청·복원 형식은 보존한다. 공개 Question·REST·WS·DB 모델은 유지한다.
- 정책·모델·호출 상한·추론 강도와 전체 근거·답변 입력을 같은 값으로 두고 비교한다.
  고정 후보의 검토 비교와 새 질문을 만드는 전체 비교를 구분해 보존한다.

## 근거와 영향

키별 점검을 고정 구조의 자료로 옮겨 응답 스키마의 반복 변경을 제거할 수 있다.
공급자의 캐시 재사용과 추론 시간은 실제 측정으로 확인한다. 스키마가 같다는 이유만으로
속도 향상이나 캐시 적중을 보장하지 않는다. 정책 축약 실험은 이 변경과 분리한다.

모델의 의미 판단은 계속 필요하다. 실제 질문에 요구가 있는지와 그 인용이 의미를
뒷받침하는지에 대한 모델·원문 평가를 유지한다. 문자열 포함 검사만으로 질문 품질을
확정하지 않는다. 실제 결과와 기본 버전 선택은 [구현 기록](../implementation.md)에 남긴다.
