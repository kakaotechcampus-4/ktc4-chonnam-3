# 0028 도메인 category 근거의 문단 ID 선택과 mobility 범위 (v2)

- 상태: Accepted
- 날짜: 2026-10-26
- 결정자: 박현솔 (AI C 역할 — JD·문서·Domain Context Builder 담당)
- 관련 PR: #99 (동한님 2026-10-08·10-12 리뷰 반영)
- 연결 항목: [0022](0022-domain-category-llm.md)의 결정 4(출력과 검증)·8(prompt version)을 대체한다. 나머지 결정은 유지한다.

## 맥락

0022 v1은 모델이 근거를 원문에서 자유 인용하고, 코드가 공백을 정규화한 원문에 그 인용이 포함되는지 확인했다. #99 리뷰에서 두 문제가 확인됐다.

1. **근거 검증 실패가 기록되지 않음.** 인용 확인이 공통 호출 계층의 validator 밖, 호출이 이미 성공으로 기록된 뒤에 있었다. 원문에 없는 인용이나 빈 인용으로 non-etc를 반환하면 최종 `etc`이지만 `failure`와 attempt의 `error_stage/error_code`가 비어, 0022 결정 4의 의미 검증 실패가 오류 조회·집계에서 빠지고 정상 `etc`와 구분되지 않았다.
2. **인용 재작성으로 타당한 판정이 버려짐.** 동한님이 실제 모델(`gpt-6-luna`, PR #114 gateway)로 원티드 공고 500건을 실행한 결과, 의료 4건·금융 3건은 분류가 업무 맥락에 맞았지만 모델이 인용을 조금 바꿔(주어 추가, 단어 생략, `++/Qt`→`C++/Qt` 보정, 비가시 문자 누락) `etc`가 됐다. 공백 처리만으로는 해결되지 않는다.

같은 실호출에서 차량 데이터 현장 지원(390950), 자동차 보안 시험 제품(388515), SDV 제어기 시험 자동화(389778)가 모두 정상 `etc`였다. 커머스 운영 SaaS·게임 운영 도구를 해당 산업에 넣는 기준이 차량 분야에는 적혀 있지 않았다.

## 결정

1. **문단 ID 입력**: 외부 입력 `DomainPostingInput`의 다섯 필드는 유지한다. LLM에는 각 필드를 `[{id, text}]` 문단 목록으로 바꿔 보낸다. ID는 `<필드>:<순번>`(예: `main_tasks:0`)이다. 목록 필드는 원래 순서를 따르고, 한 항목 안에서는 빈 줄로 문단을 나눈다. 문단 안의 줄바꿈·비가시 문자·오탈자는 고치지 않는다.
2. **ID 선택과 원문 복원**: 출력은 `{category, evidence_id}`다. non-etc는 이번 요청에 있는 ID 하나, `etc`는 `null`이다. 코드는 선택한 ID로 원문 문단을 복원해 `DomainDecision.evidence`로 돌려준다. ID는 요청별 문단 표에서만 조회하며 전역 Evidence ID로 쓰지 않는다.
3. **검증은 validator 안에서**: schema 위반은 `ContractError("schema")`, 없는 ID·non-etc의 `null`·`etc`의 ID는 `ContractError("semantic")`으로 공통 호출 계층의 validator 안에서 거절한다. 공통 gateway가 semantic 실패를 재시도 없이 `failure`와 attempt `error_stage/error_code`로 기록하고, 최종 category는 0022 결정 5대로 `etc`다. 정상 `etc`(`null` 근거)는 성공으로 남는다.
4. **mobility 범위와 산업 전용 서비스**: 특정 산업 전용 지원 서비스·SaaS는 그 산업에 포함한다. `mobility`는 차량 제어·자율주행·차량 데이터·차량 보안과 차량용 소프트웨어의 개발·시험 도구를 포함한다. 다음 경계는 유지한다.
   - 회사 업종만으로 사내 인사·ERP·일반 협업 도구를 해당 산업으로 고르지 않는다.
   - 범용 제품의 고객 중 그 산업 회사가 있다는 이유나, 목적이 드러나지 않은 기술명(로봇·LiDAR)만으로 고르지 않는다.
   - 업무와 연결되는 자격·우대 사항의 산업 지식은 보조 근거로 허용하고, 개인 취향·복지는 제외한다.
5. **version**: prompt `domain_category_v2`(`ai/prompts/domain-category-v2.md`), schema version `2`. v1 prompt와 0022는 이력으로 보존한다. 0022 결정 6에 따라 이미 판정된 공고는 재판정하지 않는다.

## 이유

- 모델이 원문을 다시 쓰지 않고 ID만 고르면 인용 재작성 실패가 구조적으로 사라진다. 원문 대조 대신 집합 포함 여부만 확인하므로 검증도 단순해진다.
- 검증을 validator로 옮기면 별도 실패 기록 코드 없이 공통 gateway의 기존 semantic 처리(무재시도·기록)를 그대로 쓴다.
- 산업 전용 서비스 기준은 이미 커머스·게임에 적용하던 것이다. 차량 분야에만 빠져 있던 것을 명시한다.
- 대안: 인용 비교를 더 느슨하게(유사도) 하는 안은 "원문에 없는 근거 거절"의 경계를 흐리게 해 채택하지 않았다. 필드 단위 ID는 근거가 너무 넓어 문단 단위로 했다.
