# 0042 — 실제 계정의 로컬 이용과 진단 수집 경계

상태: Accepted for local operation, 2026-11-09.

## 맥락

사용자는 명령어 실행을 맡기고 본인 GitHub 계정으로 서비스만 이용하려 한다.
문제 발생 시 당시의 요청·작업·면접 상태를 확인할 수 있어야 한다.
기존 전체 구현과 미병합 선행 변경, 계정 인증 정보도 보존해야 한다.

## 결정

- 원본 전체 작업을 보존한 별도 로컬 통합 worktree에서 최신 develop과 결합한다.
  통합본은 게시용 브랜치가 아니며 기존 PR의 중복 변경을 게시하는 근거로 사용하지 않는다.
- API·단일 analysis worker·실제 API를 호출하는 FE를 같은 통합본에서 실행한다.
  기존 로컬 DB·Redis·프롬프트·TTS 사용 원장을 재초기화하지 않는다.
- 로그인과 OAuth 동의, 마이크 권한은 사용자가 브라우저에서 직접 수행한다.
  세션·토큰을 대신 주입하거나 다른 브라우저의 쿠키를 복사하지 않는다.
- 서버 진단에는 요청 ID·고정 라우트·상태 코드·시간과 예외 종류·파일/함수/줄만 남긴다.
  예외 메시지·SQL·매개변수·지역변수·질문/답변 원문을 진단 로그로 복제하지 않는다.
- 프로세스·health·worker heartbeat와 시작 후 작업 상태를 로컬 보조 프로세스가 수집한다.
  DB 관측은 읽기 전용 트랜잭션의 고정 필드에 한정하고 업무 원본을 변경하지 않는다.
- 브라우저 진단은 이번 로컬 실행에만 선택적으로 붙인다. 앱 내부 HTTP·JS 오류의
  허용 메타데이터만 수집하고 외부 로그인 화면·다른 탭·DOM·콘솔·음성 원문은 수집하지 않는다.
  새 공개 서비스 API나 운영 수집 동의 정책을 추가하는 결정은 아니다.
- 진단 수집 프로세스의 지속 실행과 AI의 지속적인 자동 판단·수정은 구분한다.
  대화 턴 종료 뒤에도 로컬 수집은 가능하지만 AI가 자율 상주하며 모든 오류를 즉시 고치지는 않는다.
  질문의 적절성·답변 이해 같은 의미 문제는 사용자 관찰과 해당 면접의 원본을 함께 검토한다.

## 이유와 영향

사용자는 브라우저 이용에 집중하고, 문제를 보고하면 요청·작업 ID와 시각으로 당시 상태를 찾을 수 있다.
업무 DB에 원래 저장되는 면접 기록과 별도의 최소 진단 로그를 구분한다.
이번 로컬 준비 성공을 실제 사용자 전체 경로의 통과나 공개 운영 품질 승인으로 취급하지 않는다.
실제 파일·검증 결과·미실행 범위는 [구현 기록](../implementation.md)에 남긴다.
