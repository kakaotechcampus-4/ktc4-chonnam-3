## 맥락

공고의 문자열은 JSONB 스냅샷뿐 아니라 TEXT·TEXT[]와 요구사항에도 저장된다. 외부 응답의 NUL은
정상 저장과 추출 실패 기록을 모두 깨뜨린다. 동일 URL의 수집·추출 실패마다 새 공고 행을 만들면
재시도 횟수에 비례해 실패 행이 늘어난다. 성공 버전과 과거 run·면접의 근거는 계속 보존해야 한다.

## 결정

1. 수집 직후 PostingContent의 문자열과 문자열 목록에 실제 NUL이 있는지 검사한다. 있으면
   기존 PostingInvalidResponseError/jd_fetch_failed로 거절하고, 오염된 원문 없이 실패 상태를 저장한다.
   문자 그대로의 `\u0000` 표기는 정상 텍스트로 보존한다. raw_url의 NUL도 HTTP·저장 전에 거절한다.
2. 기존 URL advisory transaction lock 안에서 같은 URL의 최신 미참조 실패 행을 재사용한다.
   없으면 생성한다. AnalysisJob·InterviewSession이 이미 참조하는 행과 성공 행은 수정하지 않는다.
   이미 쌓인 실패 이력을 소급 삭제하지 않는다.
3. 실패 행은 최신 오류·수집 원문·시도 시각을 나타낸다. updated_at을 이번 checked_at으로 명시하며,
   더 오래된 시도의 늦은 완료는 최신 상태를 덮지 않는다. 추출 실패 다음 수집 실패처럼 원문이
   없는 상태로 바뀌면 과거 스냅샷·메타데이터·fetched_at도 비운다.
4. 실패 행은 캐시 적중으로 사용하지 않는다. 매 재시도에서 수집을 다시 수행하고 복구를 확인한다.
   성공 캐시의 TTL, 동일 내용 ID 유지, 변경된 내용의 새 버전 저장은 기존 결정을 유지한다.

## 이유와 영향

공고 테이블에는 최신 실패 상태만 재사용하고 모든 시도의 원문 이력을 쌓지 않는다. 실패 캐시·정리
작업·새 테이블을 추가하지 않으면서 반복 실패 누적을 줄인다. 실제 DB 장애는 수집 오류로 숨기지 않는다.
변경 영향은 BE 저장 경계이며 공개 API·enum·DB 스키마·migration의 추가 변경은 없다.

회귀 검증은 NUL 거절과 안전한 실패 저장, 반복·동시 실패, 시각 역전, 참조 자료 보존, 재시도 복구를
실제 PostgreSQL과 HTTP mock으로 수행한다. 실제 실행 결과는 [구현 기록](../implementation.md)에 둔다.
되돌릴 때는 코드만 이전 저장 방식으로 복원할 수 있지만, 재사용으로 덮인 과거 실패 내용은 복원할 수 없다.
