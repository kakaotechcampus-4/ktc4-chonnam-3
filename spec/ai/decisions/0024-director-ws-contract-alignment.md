# 0024 Director WebSocket을 기존 인증·연결 교체 계약에 맞춤

- 상태: Proposed, 내부 인계 구현 검토 대상. 기존 공개 계약의 준수는 사용자 지시 범위다.
- 날짜: 2026-10-23
- 관련 PR: 미게시 로컬 Director 후속 작업
- 검토자: 미지정

## 맥락

사용자는 기존 계약과 다르게 구현한 로그인 재검증·중복 연결 거절을 바로잡도록 지시했다.
공개 기준은 `frontend/docs/api-spec.md` #18이다. 로그인 세션은 handshake에서 한 번
인증하고, 연결 유지 중 로그인 세션 만료로 끊지 않는다. 중복 연결은 기존 소켓을 종료한 뒤
신규 연결을 허용한다. 이는 새로운 공개 정책을 제안하는 변경이 아니다.

## 결정과 이유

1. 답변마다 로그인 세션을 재인증하지 않는다. handshake의 쿠키·Origin·사용자 인증과,
   답변 처리의 면접 실시간 매핑·연결 소유권·DB 권한·상태 검증은 유지한다.
2. Redis Pub/Sub로 현재 소유자 nonce에 종료를 요청한다. 실제 소켓 종료 뒤 기존 잠금을
   compare-delete하고, 신규 연결은 NX 획득 뒤 수락한다. 알림 유실은 유한 획득 대기 중
   재발행하며, 프로세스 내부 소켓 목록에 의존하지 않는다.
3. 소켓 종료와 이미 수락한 답변의 분석 수명을 분리한다. 인계용 Redis 표식은 전체
   T3→Tool→T4를 감싸며, 신규 연결은 기존 처리가 끝난 DB 결과만 읽고 모델을 재실행하지 않는다.
   표식은 호출·대기·근거 조회 예산에 정리 여유를 더한 TTL을 가지며 nonce가 일치할 때만 해제한다.
4. 전송·snapshot 기록도 현재 연결 소유권을 확인한다. 소켓 종료가 끝나기 전에 연결을
   종료 상태로 바꾸거나 잠금을 해제하지 않아, 인계 대기 작업이 종료 담당 task를 먼저 취소하지 못하게 한다.

## 영향과 대체 관계

0023의 실행 연결·기존 저장 계약은 유지한다. 0023이 참조한 실행 설계의 답변별 로그인
재검증 부분을 대체하며, 단일 연결 잠금은 신규 연결 거절이 아닌 기존 연결 종료·인계에 사용한다.
OpenAPI·FE 코드·공개 메시지·전용 close code를 새로 추가하지 않는다.
여러 탭이 자동 재접속하며 서로 연결을 교체할 수 있는 기존 `PENDING_BE` 문제는 합의 완료로 처리하지 않는다.

인계 표식은 일반 실행 lease·reaper나 프로세스 강제 종료 후 복구 기능이 아니다.
DB 정지까지 포함한 전체 실행 deadline을 새로 보장하지 않는다. 준비 이벤트와 실패 단계
재개, 명시적 이탈, 음성 통합은 이번 두 계약 불일치 수정의 범위 밖이다.
실제 구현·검증 결과는 [구현 기록](../implementation.md) 한 곳에 남긴다.
