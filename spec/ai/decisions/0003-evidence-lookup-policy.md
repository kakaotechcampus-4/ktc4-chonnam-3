- 상태: Accepted, AI의 조회 필요성·결과 해석 정책에 한함
- 날짜: 2026-09-12
- 관련 PR: 없음
- 검토자: 현재 사용자 승인
- 연결 항목: [later.md의 AI-L08](../../../later.md)

## 맥락

[ForAI 4](../../../ForAI.md)는 추가 근거를 조회할 조건과 근거가 부족한 답변의 `unverified` 기준을 AI 검토사항으로 남겼다. 사용자는 다음 세 조건을 모두 만족할 때 추가 조회하고, 미발견·검증 불가·실제 불일치를 구분하는 정책을 승인했다.

## 추가 조회 조건

1. 이미 확보한 근거만으로는 해당 주장을 확인할 수 없다.
2. 확인 결과가 현재 질문·후속 질문·평가에 영향을 준다.
3. 선택된 repo의 고정 SHA와 허용된 경로 안에서 확인 가능한 주장이다.

세 조건을 모두 확인한 경우에만 추가 조회를 요청한다. 이미 충분한 근거가 있거나, 현재 판단과 관계없거나, 허용 범위에서 확인할 수 없는 주장은 추가 조회 대상으로 삼지 않는다. 질문에 포함된 구현 전제도 확인할 주장이므로 같은 기준을 적용한다.

이 조건은 조회 필요성을 정하는 AI 정책이다. service의 권한·repo/ref/path 검사와 실행 budget을 우회하는 허가는 아니다. 미정인 상한을 무제한으로 해석하지 않으며, 실제 Tool 연결에는 해당 운영값·파일 열거 방식의 합의가 필요하다.

## 결과 해석

| 실제 상황 | AI가 적용할 해석 |
| --- | --- |
| 정상 조회했지만 허용 범위에서 관련 근거를 찾지 못함 | `unverified`. 코드 부재나 거짓으로 단정하지 않는다. |
| 분석 부족·도구 장애로 확인할 수 없음 | 검증 불가 사유를 기록하고 사용자 감점에 사용하지 않는다. |
| 실제 코드와 설명이 다름 | 충돌 후보로 남기고 버전·조건을 확인하는 중립적 후속 질문을 제안한다. |

조회하지 않은 경우는 정상 조회 후 미발견과 다르다. 실제 조회 여부·확인 범위·중단 또는 미조회 사유를 보존하고, 조회하지 않았는데 Tool의 미발견 결과를 만들지 않는다.

기존 [근거 검색](../features/evidence-retrieval.md)의 출처 검증과 Tool 실행 상태·주장 지지 여부 구분을 유지한다. 원문을 찾았다는 사실만으로 주장이 맞거나 사용자가 작성했다고 확정하지 않는다. 불일치도 다른 ref·무관한 코드와의 비교가 아닌지 확인하며, 기존 `answer_vs_code`의 `verdict='unresolved'`를 유지한다.

## 이유와 대안

- 모든 주장에 추가 조회를 수행하면 이미 있는 근거와 무관한 주장도 반복해서 검색하게 된다.
- 미발견을 거짓으로 해석하면 검색 범위의 한계를 사용자 평가에 전가한다.
- 필요한 주장만 제한 조회하고 실제 실행 결과를 구분하는 안을 채택한다. 이는 비용·지연이나 판정 정확도가 검증됐다는 결론은 아니다.

## 승인하지 않은 범위

- 디렉터리 파일 열거 방식, 주변 파일 범위, 깊이·파일 수·byte/token/time·동시성 상한과 재시도 책임.
- `needs_verification`, ToolResult, claim 판정의 실제 필드·enum·JSONB·API 채택. [내부 계약](../contracts.md)은 계속 Proposed다.
- 검증 불가를 세션 준비 실패·사용자 복구 화면으로 연결하는 BE·FE 계약.
- AI-L09의 전체 정성 평가·질문 복구 정책과 AI-L15의 공개 점수 기준.

위 사항은 AI-L02·AI-L04·AI-L08 등 기존 대기 항목에서 따로 합의한다. `unverified`의 의미 승인만으로 새 DB enum을 만들지 않는다.

## 구현과 검증 인계

답변 분석은 조회 필요성을 제안하고, service/Controller가 기존 권한·범위를 검증한 뒤 Tool을 실행한다. AI 모델이 스스로 접근 범위를 넓히거나 DB·WS 상태를 확정하지 않는다.

세 조건이 모두 참인 사례와 각각 하나씩 충족되지 않는 사례를 대조한다. 미조회, 정상 미발견, 분석 부족, 도구 오류, 실제 코드 불일치를 구분하고, 원문·SHA·위치가 맞지 않는 결과로 주장을 확정하지 않는지 확인한다. 구체적인 조건은 [검증 문서](../verification.md)에 연결한다. 현재는 문서 결정이며 실행 테스트·실제 모델 평가는 아직 수행하지 않았다.
