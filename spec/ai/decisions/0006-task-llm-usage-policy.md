# 0006 작업별 LLM 사용과 요약 의미

- 상태: Accepted, AI의 Sprint 1 처리 원칙에 한함
- 날짜: 2026-09-12
- 관련 PR: 없음
- 검토자: 현재 사용자 승인
- 연결 항목: [later.md의 AI-L03](../../../later.md)

## 맥락

기존 일곱 prompt version 목록과 실제 task의 처리 방식은 구분해야 한다. 현재 Wanted 요구사항은 구조화 필드를 사용하며, Sprint 1 프로필은 완료 면접에 사용된 repo의 집계 중심이다. L1 요약에서는 프로젝트 기능과 사용자의 개인 기여를 혼동하지 않아야 한다.

사용자는 아래 처리 원칙을 승인했다. 실제 변환 version, 필드명·저장 매핑, 집계 단위는 BE와 별도 합의한다.

## 결정

| 작업 | Sprint 1 처리 원칙 |
| --- | --- |
| Wanted 요구사항 분류 | 구조화 필드를 기존 규칙으로 변환하며 LLM을 호출하지 않는다. |
| 프로필 요약 | `profile_summary` job은 유지하며 확정 데이터 집계만 수행한다. 자연어 LLM 요약은 후속 검토로 남긴다. |
| L1 요약 | 프로젝트의 기능·역할을 설명한다. README·commit 수로 사용자의 개인 기여를 추정하지 않는다. |

### Wanted 분류

기존 Wanted-only 입력과 `required/preferred/unknown`, `skill_tags` 기반 `tech_tags` 규칙을 유지한다. 원문에 없는 요구사항·기술 태그를 LLM으로 보충하지 않는다. 수집·입력 실패도 LLM이 내용을 만들어 복구하는 경로로 바꾸지 않는다.

`jd_extract` 단계와 요구사항 추출·검증·저장은 여전히 필요하다. 비호출 결정은 7개 외부 step key를 삭제·재정렬하거나 AI-L05의 JD 선행관계를 해결한 것으로 처리하는 지시가 아니다.

### 프로필 집계

입력 범위는 기존 FIX인 완료된 면접에 사용된 repo의 확정 데이터다. `report_generate` 성공 뒤 `profile_summary`를 enqueue하고 리포트 응답이 프로필 완료를 기다리지 않는 흐름은 유지한다.

Sprint 1 프로필 job에서는 LLM을 호출하지 않으며 자연어 요약을 만들기 위해 임의 수치나 개인 역할을 생성하지 않는다. 같은 repo의 반복 사용을 세는 단위·중복 제거·저장 key·갱신 실패 처리는 AI-L17과 BE 검토로 남긴다.

### L1 요약과 저장 매핑

L1의 생성 요약은 프로젝트가 제공하는 기능·역할과 확인 한계를 설명한다. 실제 개인 기여와 혼합하지 않는다. 기존 `role_summary` 이름을 유지할지, 프로젝트 요약을 어느 필드에 저장·공개할지는 BE 합의 전 확정하지 않는다.

이 의미 결정만으로 기존 개인 역할용 필드를 프로젝트 요약으로 재해석하거나 컬럼을 변경하지 않는다. 근거 없는 개인 기여 값을 빈칸 대신 추측해 채우지 않는다.

## 유지할 기준

- L1/L2, 면접 질문·답변 평가·Director, 리포트의 기존 LLM 사용 방향과 Sprint 1 논리적 모델 기준선을 유지한다. 실제 provider/API model ID 검증은 AI-L01에 남는다.
- `repo_shallow_v1`, `repo_deep_v1`, `jd_extract_v1`, `answer_analysis_v1`, `director_v1`, `report_v1`, `profile_summary_v1`의 일곱 version 목록은 삭제하지 않는다.
- prompt version이 존재한다는 이유로 LLM을 호출하지 않는다. 규칙 변환·집계 version을 prompt version으로 재정의하거나 비호출 작업을 모델 실행 결과처럼 기록하지 않는다. 실제 metadata·version 저장 방식은 BE와 맞춘다.

## 이유와 대안

- 모든 version에 대응하는 LLM 호출을 강제하면 구조화 필드 변환·확정 집계에도 모델 해석이 개입한다.
- L1 요약을 개인 기여로 사용하면 프로젝트 설명과 개인 책임을 구분하기 어렵다.
- 규칙 변환·집계와 LLM 해석의 용도를 분리하는 안을 채택한다. 호출 비용·지연·정확도의 개선을 측정했다는 뜻은 아니다.

## 남은 계약과 검증

deterministic 변환 version·출처 기록, L1 요약의 필드명·저장/API 매핑, 프로필 집계 단위·중복 제거·job 인수·저장 방식은 미정이다. 이 결정은 새 enum·DB 구조·공개 응답·점수 공식을 승인하지 않는다.

BE 전달사항은 규칙 변환과 LLM 비호출의 실행 연결, 기존 step/job 유지, 실제 metadata·저장 매핑 확인이다. 문서 기록과 담당자 전달·확인 완료는 별개이며, 이번에는 AI 문서만 갱신한다. 기존 `ForAI.md`, report와 BE·공유 문서의 과거 검토 요청을 덮어쓰지 않는다.

[검증 문서](../verification.md)에 따라 Wanted 변환·프로필 집계에서 LLM 호출이 없고, 실제 step/job·일곱 version 목록이 유지되며, L1 요약이 개인 기여를 생성하지 않는지 검사한다. 현재는 문서 결정으로 실제 모델·서비스·DB·worker 검사는 미실행이다.
