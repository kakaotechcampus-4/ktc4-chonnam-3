# 0064 Director 질문과 평가 항목의 최소 의미 적합성

상태: 2026-11-11 로컬 실험 정책으로 채택. [0052](0052-director-problem-oriented-evaluation.md)의 질문 기회·실제 관찰 구분을 유지한다.

## 맥락

Controller는 남은 배정에 맞는 evaluation_keys를 제공하고 코드는 정확한 조합을 검사한다.
이 구조적 일치는 질문 본문이 그 항목을 실제로 관찰할 수 있다는 의미적 근거와 다르다.
문제 해결이 배정돼도 변수 값이나 처리 순서의 설명만 요구할 수 있으므로, 최소 충분 답을
기준으로 새 질문의 관찰 목적을 검토할 필요가 있다.

## 결정

- 실험 정책 director_v17@semantic-fit의 신규 main에 problem_solving이 배정되면,
  명시된 문제·실패·제약 상황에서 원인 범위를 좁히는 판단, 해결 접근의 선택,
  가설을 구별할 확인 중 하나를 request에서 직접 요구한다.
- 한 판단과 그 판단의 근거면 된다. 문제 정의·진단·대안·검증·재발 방지를 모두
  한 질문에 묶는 조건을 만들지 않는다. 정보의 한계를 밝히며 필요한 확인을 고르는
  답도 허용하고, 개인의 과거 수행이 확인되지 않았으면 가정임을 드러낸다.
- 코드의 변수·상수·호출 순서를 옮겨 설명하면 직접 요청이 모두 충족되는 질문은
  이 신규 main의 문제 해결 관찰 목적에 부족하다. key·intent·배경에 문제를 언급하거나
  문장에 '판단'을 붙인 것으로 대체하지 않는다.
- 이 경우 독립 Review는 기존 plan_valid로 목적의 적합성을 판정한다. 목적 부적합과
  안전 대안이 함께 확인되면 기존 replan 경로를 사용한다. 후보별 point_coverage는
  실제로 직접 물은 내용의 검사로 유지하며 숨은 필수점을 만들어 넣지 않는다.
- 다른 평가 항목의 코드 이해 질문을 금지하지 않는다. follow_up에는 기존 계약에서
  직접 물은 미답 범위만 보완하며 새 main의 문제 해결 과제를 추가하지 않는다.
- 이전 질문·T3·원문·판정을 소급 변경하지 않는다. 충분한 코드 설명 답변이 있었다면
  그 질문의 충분성과 그 질문의 평가 적합성을 구분한다. 선언한 기회 키는 역량·점수나
  그 역량 전체의 충분한 관찰을 증명하지 않는다.

## 근거와 영향

기존 seed_score_criteria의 문제 식별·해결 과정 정의와 Director의 원인·접근·검증 관찰
원칙에 맞춘 개발용 최소 관찰 정책이다. 공식 점수 단계나 전역 분류 체계를 재정의하지
않으며 이 정책만으로 측정 타당성·출시 품질이 검증됐다고 보지 않는다.

단어 규칙 분류는 의미를 입증하지 못하고 새 응답 필드는 별도 계약 변경을 요구한다.
따라서 현재 Plan·Review 지침의 최소 보완을 선택한다. Planv4·Reviewv3, 공개 Question,
Controller 배정·저장·복구·예산·종료, DB·점수 기준과 기본 활성 catalog는 유지한다.

동일 후보의 비교, 생성·검토 확인, 시간·사용량과 남은 검증은
[구현 기록](../implementation.md)에 기록한다. 의미 판정과 실행·저장 적합성, 속도는
각각 검증하며 이 결정만으로 새 정책을 기본 활성화하지 않는다.
