# 0009 AI 평가 방법과 비교 실험

- 상태: Accepted
- 날짜: 2026-09-12
- 관련 PR: 없음
- 검토자: 현재 사용자 승인
- 연결 항목: `later.md`의 `AI-L19`, `AI-L20`, `AI-L26`

## 맥락

[0007](./0007-evaluation-design-policy.md)은 평가 자료의 출처, 독립 검수,
입력 격리와 holdout 원칙을 정했다. 그러나 실제 자료나 운영 저장소를 정하기 전에
합성 로컬 사례를 어떻게 짝지어 읽을지, 검수자 불일치와 grader 오류를 어떻게
드러낼지, 검색 방법을 어떤 비교 단위로 검증할지는 더 구체화할 수 있다.

이 결정은 그 AI 내부 방법만 확정한다. 실제 개인정보·운영 자료, 공개/DB 스키마,
출시 기준과 인프라 선택은 승인하지 않는다.

## 결정

### 합성 로컬 fixture 계약

- 합성 사례는 기존 `ai/evals/inputs/`와 `ai/evals/expectations/`에 JSON 쌍으로 둔다.
- 두 JSON은 같은 `case_id`와 `version`으로 짝을 식별한다. loader는 식별자나 버전이
  다르거나, 같은 쌍이 중복되거나, 어느 한쪽만 있는 사례를 거부해야 한다.
- 입력 쪽은 사례 식별·분류·split·source group 같은 loader 제어 정보와 실제 실행
  입력 payload를 구분한다. 모델에는 실행 입력 payload만 전달한다.
- 기대 쪽은 같은 식별자와 버전, 허용 결과, 금지 결과, 검수·control 정보를 표현한다.
  기대값, 검수 정보, control metadata는 prompt, retrieval query, tool input에 들어가지 않는다.
- 이 계약은 AI 로컬 합성 fixture에만 적용한다. 실제 운영 자료, DB나 공개 API의
  스키마, 보관 정책을 정하지 않으며 이 ADR에서 JSON 파일이나 loader를 만들지 않는다.

### 검수 불일치와 grader 검증

- 독립 검수자 사이의 불일치 사례는 양쪽의 출처 근거와 이유를 보존한 `pending`으로
  남긴다. 실제 담당자 배정, 연락·승인 경로와 실행 확인은 `AI-L19`에서 별도로 확정한다.
- 검토된 해결은 허용 결과를 넓히거나, 사례를 새 버전으로 다시 쓰거나, 근거가
  성립하지 않는 사례를 무효화할 수 있다. 모델 출력이나 모델 다수결에 맞추기 위해
  정답을 바꾸지는 않는다.
- grader는 허용 결과, 금지 결과, 의도적으로 모호한 사례, 유효하지 않은 참조,
  tool 실패 control로 점검한다. 결과는 false accept와 false reject를 control 종류별로
  구분한다.
- `pending`과 무효 사례를 전체 사례 수와 coverage에서 숨기지 않는다. 품질 지표의
  분모는 독립 검수가 끝나 판정 가능한 사례로 별도 표시하고, 제외 수와 이유를 함께
  보고한다.
- 실제 검수자, control 사례, 조정 결과, 데이터 수, 수치 임계값과 출시 승인은 아직
  완료되지 않았다.

### 통제된 비교 실험

- baseline과 candidate는 같은 사례와 source group에서 비교하고 한 번에 바뀌는 요인을
  분리한다. task별 실패, 품질, 비용, 지연을 함께 수집한다.
- 권한 거부, 잘못된 참조, parser 실패, tool 실패, 근거 source 부재를 검색 방법의
  결함과 별도 원인으로 분류한다.
- 현재 승인 범위 안의 방법 비교와 더 넓은 기능 범위를 제안하는 실험을 구분한다.
  범위 확장이 있어야 풀리는 실패 사례도 버리지 않고 별도 집합으로 보존하지만,
  실제 확장 실험과 기능 채택은 사전 승인을 받은 뒤에만 진행한다.
- 이 방법은 vector 검색, provider, model, rollout 방식을 선택하지 않는다. 측정값은
  실제 실험에서 얻은 값만 기록하고 합격 임계값은 후속 승인 전에 확정하지 않는다.

## 결과와 절충

- 쌍의 일치와 입력 격리를 loader 경계에서 검사할 수 있지만 두 파일의 버전을 함께
  관리해야 한다.
- 불일치를 억지로 단일 정답으로 만들지 않아 근거 품질을 지키지만, 판정 가능한
  품질 분모와 전체 coverage를 함께 관리해야 한다.
- 같은 사례의 통제 비교는 변화 원인을 더 잘 설명하지만, 승인 범위가 다른 실험의
  결과를 한 점수로 합칠 수 없다.

## 승인하지 않은 사항

- 실제 개인정보나 운영 데이터 사용권과 보관 위치
- 실제 검수자, adjudicator, control 자료와 사례 수
- 운영/DB/공개 API 스키마와 배포 인프라
- model, provider, vector 저장소 선택과 출시 임계값
- Sprint 2 기능 범위 확대 또는 출시 승인

## 향후 검증

구현 시 다음 검증을 추가한다.

- 정상 쌍을 읽고 mismatch, duplicate, orphan 쌍을 거부하는 loader 검사
- 모델 호출 경계에 실행 입력 payload 외 필드가 들어가지 않는 검사
- 허용/금지/모호/유효하지 않은 참조/tool 실패 control과 false accept/reject 분류 검사
- `pending`을 전체 수와 coverage에는 포함하고 품질 분모와 제외 사유를 분리하는 검사
- 같은 사례 비교와 변경 요인 기록, 실패 원인 분류, 승인 범위별 결과 분리 검사

## 기존 결정과의 관계

이 ADR은 [0002](./0002-sprint1-vector-search.md)와
[0007](./0007-evaluation-design-policy.md)에서 미결로 남긴 로컬 합성 fixture,
검수·grader 방법, 통제 비교 방법 부분만 후속 결정한다. 두 ADR의 기존 승인 내용과
결정 이력은 유지한다.
