# 0014 현행 설명 문서를 현재 코드 기준으로 유지

- 상태: Proposed
- 날짜: 2026-11-11
- 작성: FE (진영)
- 검토자: BE·AI (검토 대기)
- 관련 PR: 없음 (이 문서를 포함한 PR에서 연결)

## 맥락

용어집, 공통 계약 안내, BE·AI 아키텍처, `backend/docs/pipeline.md`, `backend/docs/db-schema.md`는 Sprint 1 FIX 기준으로 작성됐다.
이후 음성 면접, 문서 Claim 추출과 코드 대조, 리포트 이의 제기와 재평가, 명시적 리포트 재시도 등이 구현됐지만 이 문서들은 "Sprint 2 예정"으로 남아 있었다.
README에서 이 문서들을 현재 동작의 설명으로 연결하면서, 읽는 사람이 Sprint 구분을 해석해야 하고 일부 내용은 현재 코드와 반대가 됐다.

## 결정

1. 위 6개 문서는 설계 기준선이 아니라 현행 설명 문서로 관리하고, 현재 코드 기준으로 작성한다.
2. Sprint 번호로 범위를 나누지 않는다. 구현된 동작은 현재형으로, 없는 기능은 "사용하지 않는다", "미지원·향후 과제"로 적는다.
3. 결정 기록(`decisions/`), 설계 문서(`designs/`), task 문서, 구현 기록(`spec/ai/implementation.md`)은 작성 당시 기준을 보존하며 이번 변경 대상이 아니다.
4. 링크된 파일 이름의 `sprint1` 표기는 링크가 깨지지 않도록 유지한다.

## 이유

- 루트 `CLAUDE.md`의 "초기 설계 문서는 설계 기준선으로 보존한다" 원칙은 설계 판단의 이력을 지키기 위한 것이다. 이 6개 문서는 현재 구조와 규칙을 찾는 데 쓰이므로, 기준선으로 두면 틀린 현재 설명이 된다.
- 단어만 지우면 "면접은 텍스트" 같은 틀린 내용이 남으므로, 코드와 대조해 내용을 함께 고친다.

## 영향

- 영향 팀: BE·AI 문서 담당 검토 필요. 공통 API 계약(`openapi.yaml`) 변경은 없다.
- 이후 이 6개 문서는 기능 변경 PR에서 함께 갱신한다.
- `backend/CLAUDE.md`의 Sprint 기준 구현 규칙은 이번 범위에 포함하지 않았으며 별도 확인이 필요하다.

## 대체 관계

- 각 문서의 "Sprint 1 FIX" 상태 표기를 대체한다. 기존 결정 기록은 유지한다.
