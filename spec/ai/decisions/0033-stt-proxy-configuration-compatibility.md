# 0033 STT 프록시 설정의 기존 이름 호환

- 상태: Proposed — 사용자 요청에 따른 로컬 연결 보완. 운영 배포·공유 계약 승인과 구분한다.
- 날짜: 2026-11-07
- 관련: [0032 공급자 호환과 수집 예산](0032-provider-compatibility-and-source-budgets.md)
- 실행 결과: [단일 구현 기록](../implementation.md#stt-live-validation-20261107)

## 맥락

기존 로컬 환경은 STT의 MLAPI 주소를 `Whisper_Large_v3_PROXY_URL`에 두고 공통 `PROXY_TOKEN`을 사용한다.
전사 경로는 `STT_BASE_URL`·`STT_API_KEY`만 읽으므로 주소·키가 있어도 연결되지 않는다.
또한 환경 주소의 `/v1`과 전사 클라이언트의 `/v1/audio/transcriptions`가 중복될 수 있다.

## 결정과 이유

- 명시한 전용 STT 주소·키를 우선한다. 전용 주소가 없을 때만 기존 Whisper 프록시 주소를 사용하고,
  이 경로에서 전용 키가 없을 때 공통 토큰을 사용한다. 별도로 설정한 주소에 공통 토큰을 암묵적으로 보내지 않는다.
- 전사 클라이언트가 붙이는 경로와 중복하지 않도록 끝의 `/v1`만 제거한다. tenant namespace는 보존한다.
- provider·모델·언어·HTTPS 및 자격증명 검증을 유지한다. Settings 객체를 변경하거나 환경 파일을 덮어쓰지 않는다.
- 호환 연결은 기존 `MlapiSttClient`와 음성 답변 경로를 재사용한다. 다른 전사기나 외부 TTS를 추가하지 않는다.
- 무음에서 반환된 알려진 짧은 환각 문장은 기존 `empty_transcript` 규칙으로 처리한다.
  특정 테스트 문장의 성공을 모든 음성·소음·길이에 대한 인식 품질 보장으로 확대하지 않는다.

## 영향

내부 설정 호환 보완이며 FE의 음성 메시지·전사 이벤트·DB 계약은 변경하지 않는다.
실제 전사 확인과 전체 면접·리포트 통합 검증은 구분하며 실제 실행 수치·한계는 구현 기록에 둔다.
