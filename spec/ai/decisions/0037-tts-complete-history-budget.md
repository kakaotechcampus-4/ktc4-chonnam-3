# 0037 — 확인된 전체 사용 이력에 근거한 최초 TTS 예산

상태: Accepted. 2026-11-08 사용자 확인에 따른 로컬 초기화 기준이다.

## 맥락

[0036](0036-chirp3-service-configuration.md)은 실제 무료 잔여량을 확인한 뒤 월 예산을 초기화한다.
Cloud 사용량 조회 권한이 없어도 이번 달 전체 사용 이력이 빠짐없이 알려진 경우가 있다.
사용자는 같은 결제계정의 다른 프로젝트·앱까지 포함해 Chirp 3 HD 사용이 기록된
샘플 6건·174자뿐이라고 확인했다.

## 결정

1. 이번 최초 초기화의 근거는 `user_confirmed_complete_history`로 기록한다.
   이는 공급자 사용량 조회나 Cloud Console 잔여량 확인을 뜻하지 않는다.
2. 사용자 확인 범위와 실제 호출 기록이 일치할 때, 이번 달 허용량 100만 문자에서
   확인한 전체 사용량 174자를 제외한 999,826자를 최초 앱 예산으로 삼는다.
   잘못 인코딩된 진단 요청도 실제 전송한 문자 수에 포함한다.
3. 기존 `initialize_budget` 함수의 보수적 계산을 재사용한다. Cloud를 조회하지 않은 채
   관리 CLI의 `--cloud-usage-confirmed`를 사용하지 않는다. 초기화 근거·시각·기간·산식은
   별도 감사 기록과 같은 Redis 예산의 메타데이터로 보존한다.
4. 확인 이후의 모든 합성은 API와 같은 Redis 예산으로 예약·정산한다.
   공급자 직접 호출이나 다른 앱 사용이 추가되면 그 소비도 반영해야 한다.
5. 이 이력을 새 달·Redis 유실 후의 새로운 무료량으로 자동 재사용하지 않는다.
   재초기화에는 그때의 전체 사용 이력과 진행 중·불명확 소비를 다시 확인해야 한다.
   기존 `used`·`pending`·`uncertain`과 상한을 삭제하거나 임의로 늘리지 않는다.
6. 다른 앱의 사용이나 누락된 호출이 있는지 모르는 경우에는 이 경로를 사용하지 않고
   공급자 사용량 확인 또는 별도 대조가 끝날 때까지 합성을 차단한다.

## 영향

공급자·페르소나·API·DB 계약과 월 전환·Redis 교체 시 차단 정책은 바꾸지 않는다.
초기화의 근거만 구분하며 실제 검증·누적 사용량은 [구현 기록](../implementation.md)에 둔다.
로컬 앱 예산을 공급자가 보증한 잔여량이나 다른 앱까지 강제하는 전역 한도로 표현하지 않는다.
