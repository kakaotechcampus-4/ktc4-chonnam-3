# 0052. 질문 음성의 안전한 기본 낭독과 유한 복구

- 상태: Accepted for implementation, 2026-11-11
- 근거: PR #271의 일반 낭독·일시 장애·호출 기록·재시도 리뷰와 사용자의 수정·게시 요청
- 관련 결정: [0051](0051-question-speech-coverage-and-recovery.md), [0037](0037-tts-complete-history-budget.md)
- 구현·검증 원본: [리뷰 후속 기록](../implementation.md#pr271-review-fixes-20261111)

## 결정

1. 일반 낭독에서 미등록 라틴 파일명·경로 구성요소는 원래 이름을 기본값으로 둔다. 모델 실패를 이유로 글자 이름 나열을 강제하지 않는다. 기호·대소문자 비교에 필요한 차이는 모델 치환 범위 밖에서 보존한다. 승인된 읽기·숫자·폴더 관계와 코드·비밀값 보호는 유지한다.
2. 슬래시 표현은 전체 토큰의 경계를 확인해 양쪽을 처리하거나 전체를 보존한다. 유효한 `YYYY/MM/DD`는 한 덩어리로 처리하며 모호한 숫자 쌍과 잘못된 날짜를 부분 변환하지 않는다. 날짜·비율·분수·URL·경로의 의미를 새로 추측하지 않는다.
3. 발음 설정은 사용 가능·비활성·일시 조회 장애를 구분한다. 활성 버전·모델의 가벼운 조회로 실제 변경을 확인하고, 같은 식별자의 음성이 있으면 프롬프트 본문 조회·모델 호출·재합성을 생략한다. 소유권과 현재 턴 검사를 생략하는 캐시는 허용하지 않는다.
4. 일시 조회 장애는 미설정 식별자로 바꾸지 않는다. 같은 질문·모델·음성·정책에서 검증해 보관한 음성은 재사용한다. 검증된 음성이 없는 장애에서는 새 전체 TTL 기본 음성을 유료 합성하지 않고 기존 `not_ready` 경계로 안내한다. DB가 회복되거나 실제 설정·프롬프트가 바뀌면 현재 식별자를 다시 확인한다.
5. 동일 질문·모델 식별자의 캐시 수명 동안 발음 시도는 최초 포함 최대 3회다. 재시도 간격은 60초와 120초이며 새 재생 요청에서 기존 잠금 안에서만 실행한다. 최초 보관 만료를 계속 연장하지 않는다. 출력 오류·길이 초과도 다음 출력으로 회복할 수 있으므로 유한한 범위에서 재시도한다. 같은 최종 낭독문은 보관 MP3를 재사용하며 실제 새 음성만 문자를 예약한다.
6. 이 정책은 0051의 고정 60초 반복 재시도를 대체한다. 한 요청의 최대 5초·1시도·`low`·입출력 상한, 단일 실행·취소 마무리와 실제·불확실 사용량 보존은 유지한다. 변환 정책은 `question-speech.v5`로 구분하고 예산이나 기존 소비를 초기화하지 않는다.
7. 발음 호출 기록은 요청의 질문 확인 세션과 다른 세션에서 저장한다. 기록 세션의 수명은 유한하게 제한하며 알려진 DB·시간 초과 실패는 비밀값 없는 진단으로 구분한다. 기록 성공을 보장하지 못한 시도를 사용량 0으로 간주하지 않는다. 응답 직전에는 현재 질문을 다시 확인하고, 확인 불가를 통제된 음성 사용 불가로 처리한다.
8. 발음 task도 다른 runtime task와 같이 `LLM_TASK_TIMEOUTS`의 유효한 양수 설정을 받는다. 실제 발음 제한은 설정값과 5초 중 작은 값이다. recipe·설정의 수용 목록은 회귀 검사로 일치시킨다.
9. 면접 타이머와 자동 선합성 정책은 바꾸지 않는다. 현재 `/start` 이후 및 후속 질문 저장 이후의 발음·합성 대기는 시간 계산에 포함된다. 어떤 대기를 제외할지, 미시작 이탈의 선합성 비용을 허용할지는 별도 결정 대상으로 남긴다.

## 이유와 영향

일반 파일명을 철자로 강제하는 기본값과 일시 장애의 캐시 식별자 변경은 음성 품질·재생 지연·추가 합성 비용에 직접 영향을 준다. 잘못된 출력의 회복 기회를 유지하면서 질문별 누적 시도를 제한한다. 호출 기록 격리는 응답과 기록의 실패 경계를 분리하지만 DB 장애 동안 영구 기록을 보장하는 별도 장치는 아니다.

공개 REST·WS 응답, DB schema, 질문 원문, 전역 LLM timeout과 준비 작업의 시간 예산은 변경하지 않는다. 타이머를 변경하거나 미리 합성하는 기능을 이 결정으로 승인하지 않는다. 0051과 과거 실행 기록은 당시 정책의 이력으로 보존한다.
