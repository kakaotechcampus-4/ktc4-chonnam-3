# 0004 답변 정성 평가와 후속 보완 원칙

- 상태: Accepted, AI의 정성 평가 의미와 기록 보존 원칙에 한함
- 날짜: 2026-09-12
- 관련 PR: 없음
- 검토자: 현재 사용자 승인
- 연결 항목: [later.md의 AI-L09](../../../later.md)

## 맥락

답변의 충분성, 기술적 정확성, 개인 기여는 같은 판단이 아니다. 답변이 길거나 구체적이어도 틀릴 수 있으며, 구현이 존재한다고 사용자가 직접 만들었다고 확인되는 것은 아니다. 사용자는 세 판단을 분리하고, 평가 가능 여부·자료 한계·후속 보완을 구분하는 AI 정책을 승인했다.

## 세 축의 평가

| 축 | 승인된 판단 기준 | 남길 근거 |
| --- | --- | --- |
| 충분성 | 실제 질문의 핵심을 설명했는지 충분·부분·불충분으로 구분 | 실제 요구한 내용, 설명한 부분과 부족한 부분, 답변 구절 |
| 기술적 정확성 | 타당한 설명·오류·판단 보류를 구분하여 기술 | 설명이 적용되는 조건·버전과 확인 근거·판단 한계 |
| 기여·근거 정합성 | 본인·공동·타인·미확인 범위를 구분 | 사용자 발언과 자료가 확인해 주는 범위를 각각 기록 |

세 축을 하나의 점수로 합치거나 한 축의 결과를 다른 축의 판정으로 대체하지 않는다. 충분성은 실제 질문이 요구한 내용만 대상으로 하며, 답변 길이·전문용어 수를 대리 점수로 쓰지 않는다. 충분·부분·불충분을 임의 숫자로 환산하지 않는다.

기여 범위에 관한 사용자 진술과 외부 근거의 확인은 별개다. 코드 존재, README 또는 commit 수만으로 개인 작성·담당 업무를 확정하지 않는다. 유효한 대안을 모델이 선호하는 방식과 다르다는 이유로 오류로 판단하지 않는다.

## 평가 가능 여부와 보류

- 질문 오류·해석 불가 입력은 답변 평가 가능 여부부터 확인한다. 잘못된 질문 전제나 처리 오류를 사용자의 역량 부족으로 바꾸지 않는다.
- 자료가 부족하면 확인할 수 없는 판단만 보류하고 이유를 남긴다. 예를 들어 코드 확인이 불가능하더라도 답변이 실제 질문의 핵심을 설명했는지는 판단할 수 있다. 자료 부족만으로 모든 축을 자동 평가 불가로 만들지 않는다.
- 정상 제출된 “모르겠습니다”는 처리 오류가 아니다. 실제 설명한 내용에 따라 충분성을 판단하되, 기술적으로 틀린 주장이나 거짓말을 했다고 자동 판정하지 않는다.
- 추가 근거 조회와 미발견·도구 실패·코드 불일치 해석은 [0003 결정](0003-evidence-lookup-policy.md)을 유지한다.

평가 불가를 나타낼 실제 상태 enum·null 구조, 재입력 요청이나 질문 복구 방식은 이번 결정에 포함하지 않는다.

## 후속 보완과 기여 정정

후속 답변이 앞선 설명을 보완하면 관련 문답의 연결을 유지하여 이후 질문과 최종 피드백에 반영한다. 사용자가 본인 기여를 정정한 경우도 이후 질문의 전제와 피드백을 갱신한다. 최초 답변 원문과 최초 분석은 덮어쓰지 않는다.

이 원칙은 새 이력 테이블·과거 답변 편집 API·재평가 API·리포트 재생성 기능을 승인하지 않는다. 저장 형식과 원문/최초 분석을 보존하는 방식은 AI·BE가 기존 소유권 안에서 합의해야 한다.

## 이유와 대안

- 단일 종합 판정은 충분한 설명과 기술 오류, 사용자 진술과 검증 근거의 차이를 잃기 쉽다.
- 모든 자료가 갖춰질 때까지 전체 평가를 보류하면 현재 답변에서 관찰 가능한 설명도 기록하지 못한다.
- 축별로 관찰과 한계를 남기고 후속 보완을 반영하는 안을 채택한다. 정확도나 평가자 일치율이 검증됐다는 뜻은 아니다.

## 승인하지 않은 범위

- 질문 재작성·재계획·차단의 선택 조건, 사용자 입력 복구와 BE·FE 상태 전이.
- 기존 9턴·Persona 정책의 변경, HR/domain 개별 최소 횟수·고정 교대.
- Question Contract·AnswerAnalysis의 실제 필드명·enum·JSONB·schema version·API 채택. [내부 계약](../contracts.md)은 계속 Proposed다.
- 공개 점수의 공식·가중치·스케일, 품질 합격 임계값, 과거 기록 편집·재평가 이력 모델.

AI-L09는 부분 결정 완료이며, 저장 계약은 AI-L02, 공개 점수는 AI-L15, 평가 수용기준은 AI-L19와 함께 계속 검토한다.

## 구현과 검증 인계

[답변 평가](../features/answer-evaluation.md)의 의미 정책과 [검증 조건](../verification.md)을 함께 따른다. 충분성 세 분류, 길지만 오류가 있는 답변, 정상 “모르겠습니다”와 처리 오류, 질문 전제 오류, 축별 자료 부족, 기여 정정과 후속 보완·원문/최초 분석 보존을 대조한다.

이번 작업은 문서 승인 반영이다. 실제 모델 판정·서비스 통합 테스트나 DB 보존 검증은 수행하지 않았으며 수치 임계값을 정하지 않는다.

## 대체 관계
