# 0026 면접 실행 연결의 신규 구현을 분리 게시

- 상태: Proposed
- 날짜: 2026-10-25
- 선행: #82, #97, #102, #103, #107, #114, #119, #120, #124~#127
- 관련 구현: `prepare.py`, `director_service.py`, `ws.py`, 앱·worker 등록

## 맥락

기존 Director 코어와 BE 입력 경계는 별도로 게시됐다. 사용자는 로컬에 보존한 준비·답변·WS 실행과
관련 후속 보완도 현재 상태로 게시하도록 요청했다. 선행과 기존 PR의 구현을 다시 올리지 않는다.

## 결정과 이유

- 준비 worker는 소유 run·선택 repo·고정 SHA·활성 자료를 검증하고 실제 원문과 L2·Evidence를
  준비한다. 검증한 첫 질문을 저장한 뒤 시작 상태로 전환하며 빈 일반 질문으로 대체하지 않는다.
- 외부 I/O 동안 DB transaction을 유지하지 않는다. 질문 저장 전에 입력과 원문 Context를 다시
  확인하고, 답변은 분석 전에 확정해 전송·모델 실패에도 원형과 호출 이력을 보존한다.
- 최초·보강 T3는 같은 예산을 사용한다. 보강 실패를 정상 완료로 바꾸지 않고, 별도 T4를 통해
  다음 질문을 검토한다. 9번째 확정 답변의 분석 성공 뒤에만 정상 완료한다.
- WS는 기존 계약과 ADR 0024에 따라 handshake 인증·연결 교체·DB 질문 복구를 연결한다.
  연결 종료만으로 이탈하지 않고, 재접속은 저장한 답변의 모델 작업을 자동 재실행하지 않는다.
- 신규 실행 코드·설정·테스트만 게시한다. Context·L2 선행 파일 보완은 ADR 0027의 미적용
  후속 패치로 분리하며, 해당 패치를 적용하지 않은 게시본은 단독 실행 완료가 아니다.

## 영향과 검토 조건

공개 REST·WS 필드와 DB 모델·원본 migration은 변경하지 않는다. 준비 진행 이벤트, 실패 단계부터
정확한 재개, 명시적 이탈 wire, 일반 lease/reaper를 이 게시로 완료했다고 취급하지 않는다.
6/2/1은 선행 #97 정책이며, 새 수집 상한은 유한 초기 설정이지 측정된 품질·지연 목표가 아니다.
실행 명세는 #132에서, 미적용 후속 패치는 #133에서 검토하고 선행·패치와 함께 통합 재검증한다.

ADR 0023의 코어 게시 경계를 덮어쓰지 않고 실행 부분만 추가한다. 초기 설계는 보존하며 실제
실행·검증·제외 내역은 `spec/ai/implementation.md` 한 곳에 기록한다.
