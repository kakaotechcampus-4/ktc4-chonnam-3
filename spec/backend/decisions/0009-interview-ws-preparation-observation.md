# 0009 면접 WS의 준비 상태 복원과 실행 오류 구분

- 상태: Proposed, 기존 공개 계약의 구현 보완
- 날짜: 2026-10-29
- 관련 PR: #135, #136, #137
- 기존 결정: [AI 0024](../../ai/decisions/0024-director-ws-contract-alignment.md)

## 맥락

준비 화면은 `preparing` 상태에서 WS를 열어 기존 `prepareStep`·`prepareCompleted`를 기다린다.
기존 복원 함수는 현재 질문이 없으면 `question_failed`를 보내 정상 준비 중에도 실패처럼 보였다.
준비 작업과 WS 전송을 결합하거나 재연결에서 모델을 다시 호출하면 같은 준비가 중복 실행된다.
또한 답변 검증 전 LLM 설정을 읽으면 잘못된 턴까지 서버 설정 오류로 가려진다.

## 결정

1. 준비 작업은 DB의 `prepare_steps`·`status`·`last_error`를 commit하며 WS는 이를 읽는다.
   연결 시 저장된 단계 스냅샷을 보내고, 준비 중에는 약 1초마다 한 세션 행을 조회해 바뀐 단계만
   보낸다. 짧게 끝난 중간 상태는 합쳐질 수 있지만 저장된 완료·실패 상태는 복원한다.
2. 준비 중에는 질문·미완료 모델 호출 목록을 조회하거나 모델·worker를 실행하지 않는다.
   재연결은 현재 DB 상태를 다시 전달한다. 질문 전 답변은 기존 `answer_rejected`로 거절한다.
   수신 task는 준비 관찰 동안 유지하고 조회 타이머마다 취소하지 않는다.
3. 첫 질문이 저장되고 `in_progress`가 된 것을 확인한 뒤 마지막 완료 단계와
   `prepareCompleted`, 저장된 첫 `question`을 차례로 보낸다. 실패하면 해당 단계와 저장된
   `last_error`를 전달하고 닫는다. `preparing_failed` 재접속은 저장 오류 전달 후 닫는 기존
   동작을 유지한다. 이는 공개 #18의 실패 안내이며 질문·답변 실행을 허용하는 진입이 아니다.
4. 답변의 현재 턴 여부를 먼저 읽고 실제 실행 서비스도 저장 직전에 다시 검증한다.
   필요한 LLM 설정이 없으면 기존 공개 오류 형식은 유지하고 서버 로그에 별도 이벤트와
   누락·오류 필드 이름만 남긴다. 키·설정 값·답변 원문은 이 진단 로그에 넣지 않는다.
5. REST 발급과 WS 소유권 검사는 `service.py`의 공개 realtime key helper 두 개를 함께 쓴다.
   키 문자열 정의를 복사하거나 예전 이름의 wrapper를 남기지 않는다. 답변 턴 상한은 공통
   `INTERVIEW_MAX_TURNS`를 쓰며 공통 0008의 고정 9턴 정책을 바꾸지 않는다.

## 연결 수명과 영향

기존 연결 교체는 AI 0024대로 유지한다. 현재 소유자의 소켓이 닫히기 전 lock을 강제로 지우거나
덮어쓰지 않는다. 죽은 소유자의 lock은 최대 30초 TTL을 기다리고 획득은 31초 안에 종료한다.
실제 운영 proxy·브라우저의 handshake 대기 한도와 FE 재연결을 함께 확인해야 한다.

`ws:work`는 수락한 답변의 T3→Tool→T4를 소켓 수명과 분리하는 유한 표식이다. 예상되는 전송
실패가 이미 저장한 답변을 되돌리거나 같은 분석을 다시 실행하게 하지 않는다. 일반 실행 복구
lease·reaper, 임의 callback 예외의 처리, 준비 worker의 checkpoint는 각각 해당 실행 계층의 책임이다.

새 공개 메시지·오류 enum·close code·FE 변경은 없다. 실제 모델의 품질과 배포 완료를 뜻하지 않는다.
검수된 활성 prompt와 대상 도메인 frame, 유효한 모델 설정은 별도 배포 전제다.

공통 0009의 abandon REST·열린 WS 닫기·엇갈린 결과와 이벤트 차단은 #143 후속이다. 연결 끊김이나
lock 만료를 자동 `abandoned`로 해석하지 않는다. 이 보완으로 면접 전체 기능 완료를 선언하지 않는다.
실행 수치와 운영 미확인 사항은 PR 검증 기록에 남기며 기존 AI 0024 원문은 보존한다.
