# 0017 Sprint 1 추천 숫자 점수 보류

- 상태: Accepted — 숫자 점수 제공 범위와 미계산 표현
- 날짜: 2026-09-22
- 결정자: 현재 사용자
- 관련 PR: 없음
- 연결 항목: [AI-L07 구현·검수 인계](../../../ai/docs/pipeline.md#기존-id별-구현검수-인계)
- 직접 선택: 숫자 점수는 보류하고 기존 추천 표시·이유·최대 5개 추천을 유지하는 1번 안.

후속 기록(2026-09-22): 아래 작성 당시 AI-L07에 남긴 추천 대상 선정·5개 초과 처리는 사용자의 기존안 채택 위임에 따라 [0018](0018-existing-baseline-bulk-resolution.md)에서 확정했다. 기존 태그 직접 비교와 run 후보 순서를 사용하며, 당시 남은 범위를 설명한 본문은 결정 이력으로 보존한다. 0017의 숫자 점수 보류는 그대로 유지한다.

## 결정과 이유

Sprint 1에는 저장소 추천의 숫자 점수를 계산하거나 표시하지 않는다. 현재 카드 화면은 추천 표시와 이유를 사용하고, 명세에는 검증된 점수 산식이 없다. [0014 최소 변경 기준](0014-minimal-change-revision.md)에 따라 이 화면·공개 구조를 유지하고 숫자 계산을 새로 추가하지 않는다.

- 공개 `RepositoryCard.matchScore`는 기존 필수·nullable 필드를 유지하고 **null**을 반환한다. 필드를 생략하거나 0·기본 점수·기술 태그 일치율로 대체하지 않는다.
- `recommended`, `recommendReason`, `matchedRequirementIds`와 최대 5개 추천·사용자 선택 상한은 유지한다. 점수가 null이라는 이유만으로 추천을 해제하거나 추천 이유를 지우지 않는다.
- 숫자 미계산과 분석 실패는 다르다. 실패는 기존 `status`·`errorCode`로 구분하고 실패를 낮은 적합도로 표현하지 않는다. 실패 카드의 기존 표시·선택 처리를 유지한다.
- 현재 FE의 서버 제공 카드 순서와 추천 기본 선택을 유지하고 점수 정렬을 추가하지 않는다. 후보 수집용 `base_rank`·`ranking_score`를 JD 적합도 점수로 이름만 바꾸어 사용하지 않는다.
- 추천 이유·요구사항 연결은 실제 공고와 유효한 분석 근거를 사용한다. 공고 전체 기술 태그의 겹침만으로 개별 요구사항이 충족됐다고 단정하거나 모든 요구사항 ID를 연결하지 않는다.

## 기존 흐름과 저장

외부 7개 분석 단계와 `match_score` 단계 이름은 유지한다. 해당 단계에서 추천 카드 정보를 만들되 숫자 점수를 만드는 작업만 보류한다. 기존 `repo_match_scores` 저장 위치와 카드 API 필드를 유지하며 새 테이블·점수 상태 필드·추가 모델 호출을 요구하지 않는다.

실제 DB 모델은 아직 골격이므로 score 컬럼이 이미 null을 허용한다고 주장하지 않는다. null 저장·응답 변환·추천 근거 연결은 기존 저장 경계 안에서 구현 시 확인한다. 기존 구조에 제약 충돌이 실제로 있으면 그 영향을 검토하고 가짜 숫자로 우회하지 않는다. 기존 mock의 숫자 예시는 구현 연결 시 이 정책에 맞춘다.

이 결정은 문서상의 제공 범위 확정이다. 코드·DB migration·실제 화면·fixture 수정이나 추천 동작 검증을 완료했다는 뜻은 아니다. 면접 리포트의 필수 숫자 점수 정책은 별도이며 그대로 유지한다.

## 검증과 남은 범위

- 성공 카드도 `matchScore` 필드를 포함하고 null을 반환한다. null만으로 실패·추천 해제를 판단하지 않는다.
- 추천 표시·이유·기본 선택·최대 5개 제한과 기존 카드 제공 순서가 유지된다.
- 실패 카드가 낮은 점수의 성공 카드로 바뀌지 않으며 실제 근거 없는 요구사항 ID가 연결되지 않는다.
- 7개 단계·기존 저장 위치·공개 필드를 유지하고 새 숫자 계산·표시·점수 정렬·모델 호출을 추가하지 않는다.

AI-L07의 Sprint 1 산식·스케일·숫자 정렬·점수 동률 처리와 미계산 표현 선택은 해소한다. 실제 JD 근거에 따른 추천 대상 선정과 관련 후보가 5개를 넘을 때의 선택 기준은 아직 확정되지 않았으므로 AI-L07에 남긴다. 기존안이 충분한지 먼저 확인하며 저장 키·직렬화·필드 연결은 별도 사용자 질문으로 쪼개지 않는다. 후속 숫자 점수 도입은 실제 필요와 근거가 생길 때 검토한다.
