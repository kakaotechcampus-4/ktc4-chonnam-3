# 0005 도메인 질문 생성과 개발용 후보 유지

- 상태: Accepted, AI의 질문 생성 정책과 개발용 후보 유지에 한함
- 날짜: 2026-09-12
- 관련 PR: 없음
- 검토자: 현재 사용자 승인
- 연결 항목: [later.md의 AI-L10](../../../later.md)

## 맥락

[ForAI 3](../../../ForAI.md)은 도메인 frame, `etc` fallback과 기술 질문 중복 방지를 AI 검토사항으로 남겼다. category 7개·각 3개 frame은 기존 FIX이며, [도메인 프레임 문서](../features/domain-frames.md)에 21개 후보가 있다.

사용자는 기존 문구를 개발용 후보로 유지하면서 다음 질문 생성 정책을 승인했다. 이는 운영 seed의 최종 문구 승인·검수 완료가 아니다.

## 결정

1. 현재 21개 문구를 개발용 후보로 유지한다. 이번 결정에서 후보 문구를 수정하거나 운영 seed를 설치하지 않는다.
2. 도메인이 없거나 신뢰하기 어려우면 산업을 추측하지 않고 `etc`를 사용한다.
3. 한 번에 하나의 중심 목적을 묻는다. 확인되지 않은 경험·조건은 가정형으로 표현하며 실제 경력이나 프로젝트 사실로 단정하지 않는다.
4. 기술 질문을 반복하기보다 서비스 운영·사용자 영향·판단 이유를 묻는다. 기술 내용의 언급 자체를 금지하는 것은 아니지만, 같은 구현 질문을 표현만 바꿔 반복하지 않는다.
5. JD 자격요건 충족 여부를 검사하거나 사용자의 실제 산업 경력을 단정하는 질문으로 바꾸지 않는다.
6. 법률·의료적 정답을 보증하거나 도메인 전용 점수를 만들지 않는다.

기존 Persona·9턴 정책은 유지한다. domain 질문을 배정할 최소 횟수나 고정 교대는 이 결정으로 추가하지 않는다.

## 이유와 대안

- 미확인 도메인을 추측하면 이후 질문이 사실이 아닌 전제에 의존하게 된다.
- frame을 그대로 낭독하거나 기술 질문을 반복하면 현재 서비스 맥락과 질문의 목적이 맞지 않을 수 있다.
- 개발용 후보와 생성 제약을 분리해 유지하는 안을 채택한다. 확인된 맥락에서는 중심 목적에 맞게 구체화하고, 미확인 조건은 가정으로 남긴다.

이 결정은 21개 문구의 운영 품질이나 실제 모델의 정책 준수율이 검증됐다는 뜻이 아니다.

## 승인하지 않은 범위

- 운영 seed의 최종 문구 채택·수정, 문구별 독립·도메인 검수와 한국어 표현 검토 완료.
- category 신뢰 판단을 위한 실제 입력 계약·근거 구조·수치 임계값.
- 활성 version 선택, 검토자 metadata, table column·저장·migration·seed 설치 방식.
- 별도 도메인 Agent, 외부 지식 조회·vector 도입, 새 API·점수·평가 합격 기준.

`domain_question_frames`의 기존 저장 소유권을 유지한다. 개발용 후보를 사용한다는 이유로 runtime 코드에 질문을 하드코딩하거나 검수되지 않은 운영 seed를 활성화하지 않는다. 상세 구현은 기존 [내부 계약](../contracts.md)과 BE 검토를 따른다.

## 구현과 검증 인계

category가 없는 경우와 신뢰하기 어려운 경우의 `etc` 사용, 확인된 category 보존, 미확인 경력·조건의 가정형 표현, 중심 목적 하나, 기술 질문 중복·JD 검사·전문적 정답 보증·점수화 방지를 [검증 조건](../verification.md)으로 확인한다.

후보 표는 category별 3개·총 21개를 유지하며 실제 원문 변경 여부도 확인한다. 운영 승인·독립 검수·DB 설치는 별도 기록이 있어야 완료로 표시한다. 현재는 문서 결정이며 실제 모델·서비스·seed 설치 검사는 미실행이다.

## 대체 관계

[0001 기준선](0001-ai-baseline.md)의 AI-L10 관련 보류 중 질문 생성 정책·개발용 후보 유지 부분만 후속 결정으로 대체한다(부분 Superseded). 기존 기록과 0002·0003·0004의 결정은 유지하며 운영 seed와 저장·검수 세부는 계속 대기다.
