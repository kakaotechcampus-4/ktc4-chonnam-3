# 0040 — Director 입력의 원문 중복 제거

상태: Accepted for local development. 2026-11-08 사용자 요청의 후속 구현 기준이다.
사람의 질문 품질 검수나 공개 서비스의 운영 승인을 대신하지 않는다.

## 맥락

Director의 Context에는 코드 Evidence·공고 요구사항·지난 답변·보완 원문이 있다.
서버는 이 원문으로 허용된 참조 전체를 구성하고 모델의 근거 ID와 인용을 검증한다.
같은 참조 목록을 원문과 함께 모델에도 다시 전달하면 Context와 내용이 중복된다.
실제 긴 코드와 여러 문답이 있는 입력에서는 검증에 필요한 정보를 더하지 않으면서
유한한 모델 입력 상한을 소비한다.

## 결정

- 서버의 전체 참조 map과 Context의 모든 원문·위치·버전·문답 이력은 보존한다.
- 모델에는 Context 원문을 한 번 전달한다. 별도 `reference_texts`에는 Context 밖에서
  명시적으로 허용한 `job_posting` 원문만 넣는다.
- Context 밖의 다른 참조, 충돌하는 원문, 존재하지 않는 근거 ID는 계속 거절한다.
  같은 텍스트라는 이유만으로 다른 종류·ID·기여 주체의 근거를 합치지 않는다.
- 현재 질문 계약·답변·검증된 분석과 모든 과거 분석을 보존한다.
  원문 길이·턴 수를 이유로 조용히 과거 답변이나 기여 정정을 잘라내지 않는다.
- 자동 Director와 준비된 질문의 기존 진입점은 같은 투영 함수를 재사용한다.
  Plan과 독립 Review의 유한한 두 시도, 기존 출력 계약과 참조 검증은 유지한다.
- 입력 상한은 262144bytes로 유지한다. 실제 gateway 직렬화 크기에 대한 회귀 검사를
  적용하며, 중복 제거 뒤에도 초과하는 입력은 기존 예산 실패로 명시한다.

## 이유와 영향

중복된 직렬화만 제거하면 근거·히스토리 손실 없이 모델 입력을 줄일 수 있다.
상한 확대, 질문 후반부의 이력 삭제, 서버 참조 검증 생략은 채택하지 않는다.
기존 프롬프트는 `Context`와 `reference_texts`의 근거 사용을 허용하므로
프롬프트 버전·공개 API·출력 스키마의 변경은 필요하지 않다.

0038·0039의 원문 보존·유한 예산·단일 Director 원칙을 구체화한다.
이 투영만으로 모든 크기의 레포·대화가 상한 안에 든다고 보장하지 않는다.
실제 실패 재현·회귀·새 면접의 검증 결과와 게시 상태는 [구현 기록](../implementation.md)에 둔다.
