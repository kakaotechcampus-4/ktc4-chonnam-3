# 0007 평가자료 분리와 검수·결과 기록 원칙

- 상태: Accepted, AI의 평가 설계 정책에 한함
- 날짜: 2026-09-12
- 관련 PR: 없음
- 검토자: 현재 사용자 승인
- 연결 항목: [later.md의 AI-L19](../../../later.md)

## 맥락

개발에 사용한 자료로 최종 품질을 주장하거나, 기대 정답을 모델 입력에 노출하거나, 성공 결과만 보고하면 평가를 신뢰하기 어렵다. 사용자는 평가자료 구성·분리·검수·결과 기록 원칙을 먼저 확정하고 수치 목표와 출시 기준은 별도 합의로 남기는 방향을 승인했다.

## 결정

1. 사례는 자료·근거, 질문·답변·다음 행동, 면접 흐름, 리포트의 네 종류로 구성한다.
2. 같은 원본 프로젝트에서 파생한 사례는 같은 source group으로 묶어 개발용·최종검증용 자료 간 유출을 막는다. 개별 질문이나 파일만 나누어 같은 프로젝트의 파생 사례를 양쪽에 배치하지 않는다.
3. 기대 결과와 금지 결과를 구분하고 작성자 외 검수자가 확인한다. 원문·질문 범위·승인된 정책을 근거로 검수하며, 실제 검수자·날짜·결과는 확인 후 기록한다.
4. 기대 정답·검수 메모는 모델 prompt·retrieval 입력에서 제외한다. 실제 운영에서도 제공되는 질문·원문·Question Contract와 평가 전용 정답을 구분한다.
5. 최종검증 자료를 보고 기능을 수정했다면 그 자료는 이후 회귀검사용으로 분류한다. 같은 source group의 파생 자료를 복사·이름 변경하여 새로운 미사용 최종검증 자료처럼 취급하지 않는다.
6. 실패·보류·미실행도 기록한다. 중대한 안전 오류를 평균 품질 점수로 상쇄하지 않는다.

## 개발·최종검증·회귀의 구분

개발용 자료는 구현·prompt·정책을 조정하는 데 사용한다. 최종검증용 자료는 해당 개발·조정에 사용하지 않은 source group으로 분리한다. 이후 개발에 사용한 최종검증 자료는 독립적인 최종검증 근거로 재사용하지 않고 회귀검사 자료로 다룬다.

재분류는 기존 평가 이력을 삭제하거나 원문을 바꾸라는 뜻이 아니다. 어떤 버전의 평가 이후 어떤 목적으로 사용했는지 남긴다. 현재 이 결정으로 실제 데이터셋을 분할·이동하거나 새로운 최종검증 자료를 확보한 것은 아니다.

## 검수와 결과 해석

기대 결과는 원문과 승인된 AI 정책에 연결한다. 여러 답변·행동이 타당할 수 있는 경우는 기존 검증 문서의 허용 결과와 목적을 검수한다. 독립 검수 절차의 승인을 개별 사례의 검수 완료로 해석하지 않는다.

결과는 통과·실패·보류·미실행·범위 밖을 구분하여 보고한다. 미실행을 성공으로 계산하거나 실패·보류를 누락하지 않는다. 수치 결과에는 대상·분모·오류 유형을 함께 기록하고, 미수집 값을 추정치로 채우지 않는 기존 원칙을 유지한다.

다른 사용자 자료 노출, 없는 근거 생성, 답변 원문 변형, 종료 후 질문 확정 등의 중대한 오류는 평균 품질이 높다는 이유로 지우지 않는다. 이 원칙은 정확도 목표·오류 허용률·출시 승인을 새로 정한 것이 아니다.

## 이유와 대안

- 개별 사례만 무작위로 나누면 같은 원본의 내용이 개발과 최종검증에 함께 들어갈 수 있다.
- 검수 메모를 모델 입력에 넣거나 성공한 시도만 집계하면 실제 처리 능력과 평가 결과를 구분하기 어렵다.
- source group 분리, 독립 검수, 평가 전용 정답 격리, 전체 결과 기록을 채택한다. 실제 평가 정확도·검수자 일치율이 검증됐다는 뜻은 아니다.

## 승인하지 않은 범위

- 최종 표본 수·유형별 비율·split 비율, 정확도·비용·지연·동시성 목표와 출시 기준.
- 개별 사례의 기대 결과·허용 행동 최종 검수, 검수 불일치의 상세 해결 절차와 실제 담당 배정.
- 실제 provider/model 적합성, 채점기 정확도·오류 심각도 수치, 실행 환경·예산·반복 횟수.
- 사례 파일의 정확한 schema·저장·배포 방식, 자료 사용 동의·접근권한·보존/삭제 정책. 특히 production DB에 `eval_cases`·`eval_runs`를 새로 만들지 않는다.

기존 초기 15~20건은 구축 절차를 시험하는 제안 규모이며 이번 결정으로 확정하지 않는다. 실제 표본 수와 목표는 실측·팀 합의 후 기록한다. 자료 운영은 AI-L18, 공개 점수는 AI-L15의 별도 경계를 유지한다.

## 검증 인계

[검증 문서](../verification.md)에서 source group 중복, 기대 정답·검수 메모의 실행 입력 혼입, 미검수 사례의 완료 오표시, holdout 재사용, 결과 누락과 안전 오류 비상쇄를 확인한다. 정책 승인과 실제 사례 구축·검수·모델 평가·출시는 별개다.
