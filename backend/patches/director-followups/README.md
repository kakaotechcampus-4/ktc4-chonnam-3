# Director Context·L2 후속 패치

이 디렉터리는 **아직 Python 소스에 적용하지 않은 검토용 변경**이다. develop에 없는 선행
파일 전체를 복사하지 않고 이번 신규 수정 구간만 보존한다. 이 자료가 병합돼도 기능이 활성화되지
않으며, 앱·worker·빌드·CI는 패치를 자동 적용하지 않는다.

## 대상과 선행

| 순서 | 대상 | 신규 변경 | 선행 |
| --- | --- | --- | --- |
| 1 | `agent_context.py` | 현재 답변 Context·9번째 답변·실제 미확인 범위 전달 | #82 |
| 2 | `answer_context.py` | 현재 질문 loader와 반환형 | #126 및 패치 1 |
| 3 | `repo_deep.py` | 공유 budget·호출 기록·프록시·수집 한계 전달 | #119, #114 |
| 4 | Director `agent.py` | 기존 생성 함수에 프록시 base URL 전달 | #82, #126, #114 |

`manifest.json`에는 대상 경로, 선행 PR/head, 정확한 base/result Git blob과 패치 SHA-256을
기록한다. 패치 4의 base는 #82 생성 함수와 #126 실행 어댑터를 결합한 로컬 기준이다.
manifest의 선행 commit은 자동 병합 지시가 아니며 최신 변경은 별도로 검토한다.

## 적용 조건

1. 선행을 반영한 별도 로컬 환경에서 대상 파일의 `git hash-object`가 `base_blob`과 같은지 확인한다.
2. 패치 파일의 SHA-256을 확인하고 순서대로 `git apply --check <patch>`를 수행한다.
3. 검토한 패치를 적용한 뒤 대상 파일의 blob이 `result_blob`과 같은지 확인한다.
4. 현재 질문·마지막 답변·원문 한계·L2 예산·호출 기록의 회귀 검사와 실제 실행 연결을 재검증한다.
5. 일반 코드 후속 변경으로 반영할 때에는 미적용 패치와 중복하지 않도록 처리하고 적용 기록을 남긴다.

base가 다르면 자동·강제·모호한 적용을 하지 않고 신규 선행에 맞춰 패치와 검증을 갱신한다.
선행 코드·테스트·의존성은 이 PR에 포함하지 않는다. 원본 전체는
`backup/director-unpublished-before-pr-20261025`와 기존 로컬 worktree에 보존한다.

실행 service에 의존하는 회귀 검사는 별도 면접 실행 구현 PR에 둔다. 패치 자료 단독 검사는
해시·형식·정확한 선행에 대한 적용 가능성을 확인하며 모델 품질·서비스 실행 성공을 뜻하지 않는다.
실제 검증 결과는 관련 실행 PR의 `spec/ai/implementation.md` 한 곳에 기록한다.
