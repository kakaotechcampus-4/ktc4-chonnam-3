# 0004 면접 질문 배분의 기존 기준 복원

- 상태: Accepted — 배분 정책 복원, 실제 제어 구현·검증은 대기
- 날짜: 2026-09-22
- 결정자·검토자: 현재 사용자
- 관련 PR: 없음
- 결정 근거: `spec/backend/features/interview.md`의 배분 변경을 검토한 뒤 사용자가 “그럼 그렇게 기존대로 정하자.”라고 승인함.

## 이유와 범위

[0002](0002-local-policy-baseline.md)는 로컬 설정 예시의 기술/도메인/HR 6/2/1을 채택했다. 실제 횟수 제어는 아직 미구현이며, 이 배분에서는 첫 HR 질문 뒤 HR을 다시 선택할 수 없다. 사용자는 기존 설계처럼 답변에 따라 질문 관점을 조절할 수 있도록 면접 배분만 복원하기로 했다.

## 결정

1. 정상 면접은 9턴이며, 첫 질문은 `hr_manager`로 고정한다. 첫 질문도 전체 횟수와 HR 횟수에 포함한다. Director의 정상 조기 종료는 허용하지 않는다.
2. `tech_lead`는 목표 6턴, 최소 5턴이다. `domain_lead + hr_manager`는 합산 최소 3턴이다.
3. 도메인·HR의 개별 횟수와 첫 질문 이후의 순서는 고정하지 않는다. 2턴부터 Director가 답변 맥락에 따라 선택하며, HR의 추가 질문도 허용한다.
4. Controller는 이미 제시한 질문과 남은 턴으로 위 최소 조건을 충족할 수 있는 Persona 후보를 제한한다. 기술 질문 6턴은 목표이며 정확히 6턴을 강제하는 조건이 아니다. 정상 9턴에서 기술 질문이 5턴이면 도메인·HR 합계는 4턴이다.
5. 사용자 이탈·실패로 중단된 면접에 정상 완료 배분을 강제하지 않는다. 기존 9번째 답변 처리 후 종료·답변 보존·재시도 정책은 유지한다.

## 반영과 검증

- [BE Turn 정책](../../backend/features/interview.md#turn-정책), [AI Director 기준](../../ai/features/interviewer.md#고정-9턴-정책), 내부 `allowed_personas` 설명과 작업·검증 지침을 함께 맞춘다.
- 실제 코드에서 소비하지 않는 `.env.example`의 고정 `PERSONA_TURN_QUOTA` 예시는 제거하고 복원한 배분을 한국어 주석으로 안내한다. 새 환경변수나 배분 제어 코드를 추가하지 않는다.
- 구현 시 첫 HR 질문·기술 목표와 최소 횟수·도메인/HR 합산 최소 횟수·HR 재선택·9턴 종료를 검증한다. 현재 문서 검사를 실제 Director 동작 검증으로 보고하지 않는다.
- DB 구조·공개 API·화면 변경은 없다. 포트폴리오 20MB, 공고 재사용 7일과 나머지 확정 정책은 유지한다.

## 대체 관계

[0002](0002-local-policy-baseline.md)의 6/2/1 고정 배분만 대체한다. 기존 결정 본문은 이력으로 보존하고 현행 배분은 이 결정을 따른다. [AI 0014](../../ai/decisions/0014-minimal-change-revision.md)의 HR·도메인 개별 배분 비고정 기준을 복원하며, 공고 TTL의 7일 변경은 유지한다.
