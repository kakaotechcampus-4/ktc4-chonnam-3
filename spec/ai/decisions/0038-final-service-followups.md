# 0038 — 최종 서비스의 기준 초기화·작업 전달·검증 경계

상태: Accepted for local development. 2026-11-08 사용자 요청에 따른 로컬 구현 기준이다.
공유 API 변경의 팀 검토·병합과 운영용 평가 기준 승인은 별도다.

## 맥락

사용자는 사람의 평가셋·rubric 검수를 보류하고 남은 AI 기능 구현과 자동 검증을 요청했다.
#206은 새 환경의 비활성 rubric으로 리포트가 실행되지 않는 문제를 제기한다.
기존 prompt 등록 도구만으로는 기준과 질문 프레임의 사용 상태를 준비할 수 없다.
보고서 저장 뒤 프로필 큐 전달이 실패하는 경우에도 작업을 복구할 수 있어야 한다.

관련 이슈는 #206, #207, #208, #209, #210, #211이다.
과거 구현·검증 기록은 덮어쓰지 않으며 새 결과는 [구현 기록](../implementation.md)에 추가한다.

## 결정

1. **개발 기준 초기화는 운영 승인과 구분한다.**
   개발·시험 profile, 환경, 호스트·포트·DB, 미검수 초안 사용을 명시한다.
   기본은 dry-run이며 적용은 별도 선택한다. 정확한 6개 평가 key와 0~4 단계,
   21개 질문 프레임의 본문·지문을 검사한다. 활성·비활성 기존 본문이 다르면 중단한다.
   등록·활성화는 한 transaction으로 처리하고 대상 지문·실행자·시각·미검수 상태를 남긴다.
   같은 대상을 다시 실행해도 기존 행·시각·본문을 변경하지 않는다.

2. **모델과 실제 실행 상한은 설정·배포 버전에 묶는다.**
   사용자가 선택한 sol, xhigh, 스트리밍 설정을 prompt 배포 manifest에 반영한다.
   배포 식별자를 붙인 버전은 최대 100자로 제한하고 등록 전에 검사한다.
   20자를 넘는 감사 버전이 있으면 해당 컬럼의 축소 downgrade를 거절한다.
   과거 버전을 잘라내거나 기록을 삭제해 migration을 통과시키지 않는다.

3. **문서·음성 모드는 공개 계약과 실제 동작을 함께 맞춘다.**
   포트폴리오·자소서 구분, 선택 자소서 ID와 지원 문서 형식·상한을 명시한다.
   새 voice 세션의 텍스트 WS 제출은 저장·STT·모델 실행 전에 거절한다.
   기존 text 세션은 그 모드로 복구하고 텍스트 입력을 유지한다.
   음성 실패가 voice 세션을 조용히 text 세션으로 바꾸게 하지 않는다.

4. **프로필 갱신 의도는 보고서 성공과 같은 transaction에 저장한다.**
   보고서·revision별 outbox 요청을 영구 기록하고 결정적 전달 ID를 사용한다.
   전송 실패, worker 중단과 lease 만료는 유한 reaper로 복구한다.
   총 시도 5회·24시간, 유한 페이지와 backoff를 적용하고 종료 사유를 남긴다.
   만료 작업이 최신 결과를 덮어쓰지 못하게 인수·저장·완료 시점을 검증한다.
   비활성 사용자에게는 신규 생성·기존 캐시 저장도 실행하지 않는다.

5. **보완 조회 후보와 읽은 근거를 구분한다.**
   실제 고정 SHA에서 열거한 선정 경로와 주변 후보를 한도 안에 보존한다.
   후보 경로가 있다는 이유만으로 Evidence를 만들지 않는다.
   일반 파일의 실제 원문·줄 위치를 읽고 소유권·공개 상태·SHA를 다시 검증한 뒤 저장한다.
   완전한 재귀 tree 응답으로 깊은 여러 모듈에 접근하되 요청·바이트·깊이·항목 상한을 유지한다.
   불완전한 부모 목록은 완전 캐시로 저장하지 않는다. 미방문·미확인 범위를 전달한다.
   면접 중 보완 판단은 단일 Director의 Tool 요청이며 자율 분석 Agent를 추가하지 않는다.

6. **복구 순회는 한 번의 페이지 예산 밖에서도 진행한다.**
   준비 복구 두 경로는 공통 keyset 순회와 회차 간 cursor·cutoff를 사용한다.
   각 작업의 문맥을 얕게 복사하는 ARQ에서도 같은 worker의 순회 상태를 공유한다.
   이를 위해 기존 worker 기능·cron을 삭제하지 않는다.

7. **자동 실행과 사람의 품질 승인을 별도 상태로 기록한다.**
   입력 계약, 실제 서비스 실행, 결과 형식, Judge 제어 사례, 진단 Judge 실행을 구분한다.
   검수 전 사례도 통과한 자동 검사에는 `자동 검증 완료`로 기록한다.
   사람 검수 상태는 `deferred`로 남기고 검수자·approved·품질 gate를 만들어 채우지 않는다.
   합성 holdout은 독립 계약 검증용이며 비공개 출시 품질 평가셋으로 부르지 않는다.
   Judge의 정답·출처 부족, 불일치와 미실행 안정성 검사는 그대로 보고한다.
   Judge에는 실제 사례의 원문·참조·위치·질문 계약·담당·Tool 상태만 버전이 있는
   whitelist로 전달하고 64KiB 상한·누락·미지원 범위를 표시한다.
   저장된 출력의 재판정은 입력·기대값·출력 지문과 binding을 확인한 뒤 실행한다.
   서비스 모델을 다시 실행하거나 기존 실패·출력·정답을 바꿔 판정에 맞추지 않는다.
   보고서의 실제 검증된 내부 Claim은 문구·구분·담당·순번·턴/근거 참조를 함께
   별도 artifact와 지문으로 보존한다. 공개 응답이나 원문으로부터 참조를 추측하지 않는다.
   이전 자료의 전역 원문을 새 합성 입력에 연결할 때는 사용 가능 자료라는 새 전제를
   명시한다. 원래 그 턴에 사용됐거나 실제 코드 버전이 입증됐다고 해석하지 않는다.
   조회 결정 함수·모델 질문 생성·Tool I/O는 실제 실행한 단계별로 나누어 평가한다.

8. **평가 컨테이너에는 실행 코드만 담는다.**
   사례·holdout·키를 이미지에 복사하지 않는다. 사용자가 고른 사례를 읽기 전용으로 연결한다.
   기본 실행은 네트워크 없는 입력 계약 검사다. 실제 공급자 실행에는 manifest와 총 시도
   예산을 별도로 명시한다. CI에는 유료 공급자 키를 주입하지 않는다.

9. **실제 검증의 범위와 데이터를 보존한다.**
   고정 SHA·원문 지문·원문 위치·모델 입력·시도·실패·저장 결과를 함께 남긴다.
   서비스 함수, 실제 공급자, 작업 큐, 컨테이너 API와 브라우저의 검증을 구분한다.
   합성 질문·가상 지원자·시험 인증 세션을 실제 개인 기여나 OAuth 실사용으로 해석하지 않는다.
   실제 공개 공고와 합성 Wanted 응답을 사용한 혼합 검증도 구분한다.
   기존 TTS 예산은 같은 Redis에서 소비하고 추가 무료량을 초기화하지 않는다.

## 영향

새 migration은 프로필 갱신 outbox와 prompt 버전 용량 확장이다.
기존 질문·분석·보고서 revision·기준 본문·프로필 생성 감사 이력은 보존한다.
초기 설계 파일에는 구현 여부를 기록하지 않는다. 구현·실행·회귀 결과는 한 곳에 추가한다.
로컬 전체 통합 검증은 커밋·PR·병합·배포나 운영 품질 승인으로 확대 해석하지 않는다.
