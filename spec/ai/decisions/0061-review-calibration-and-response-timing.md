# 0061 독립 검토의 판단 경계와 응답 구간 계측

상태: 2026-11-11 로컬 실험 개발·평가 채택.

## 맥락

질문 계약의 필수점을 모두 직접 물어도 여러 독립 과제를 한꺼번에 요구하거나 프로젝트와
직무의 관계를 일반 진단 질문으로 대체할 수 있다. 기존 Review gate는 부정 판정을
반려하지만 모델이 이 경계를 넓게 해석하면 승인된다. 질문 길이 감소만으로 검토 품질이나
준비 속도 개선을 확정할 수 없다. 기존 호출 합계만으로 공급자 대기·본문 수신·로컬 검증
시간을 각각 알 수도 없다.

## 결정

- 첫 보완은 기존 v17의 새 정책 변형으로 둔다. Review의 독립 판단과 직무 관계 기준만
  구체화하고 공통·생성 지침, Planv4·Reviewv3, payload와 intent 입력은 보존한다.
  코드가 반려 결과를 강제로 만들거나 특정 레포·문장·정답을 매칭하는 규칙을 추가하지 않는다.
- 한 선택과 그 선택의 이유, 한 검증의 입력과 관찰 결과는 같은 판단일 수 있다. 실제로
  충분히 답한 후에도 별도 적용·차이·보완·검증을 각각 답해야 한다면 독립 과제를 구분한다.
  단일 intent·필수점·문장으로 묶였다는 이유로 하나의 판단이라 인정하지 않는다.
- company_job_fit은 프로젝트의 실제 방식과 직무 조건의 관계가 답에 필요해야 한다.
  일반 지표·진단 방법만으로 요청을 충족할 수 있는지 확인하되, 특정 프로젝트 동작의
  직무상 효과를 판단할 지표와 그 선택 이유는 같은 관계 판단일 수 있다. 표시되지 않은
  추가 설명을 채점 의무로 만들지 않는다.
- 검토 품질은 보존한 고정 후보에 같은 입력·스키마·설정으로 두 정책을 적용해 비교한다.
  원문 수용/반려 일치, 복구 분류, 유효 대안의 보존, 호출 실패, 시간·사용량을 구분한다.
  기존 평가 원문·정답·실행을 수정하지 않고 새 선택표와 oracle는 모델 입력 밖에 둔다.
- 응답 계측은 사적 실행 장부 metadata에 version 1의 허용 키로 추가한다. attempt 시작을
  기준으로 헤더·첫 SSE 이벤트·첫 비어 있지 않은 output_text.delta의 도착을 기록하고,
  본문 읽기·응답 해석·작업 validator의 실행 시간은 별도 구간으로 기록한다.
- 응답 해석 구간은 공급자 봉투/SSE 완료 응답 파싱, 모델·완료·ID 확인, 최종 출력의 strict
  JSON 해석까지다. 작업별 계약 validator는 별도 validation_ms다. 실제로 도달하지 않은
  시점·구간은 null이고 과거 미계측 기록은 새 키가 없다. 새 버전의 0은 실제 관측 값이다.
- SSE의 시간은 완성된 이벤트를 포함한 chunk를 수신한 로컬 시각이다. 토큰 생성·생각 시작
  시각을 추정하지 않는다. delta가 없는 완료 응답에는 첫 delta 시간을 만들지 않는다.
  계측용 현재 frame의 메모리는 64KiB로 제한하고, 한계에 이르면 제한 상태를 남긴다.
  기존 권위 파서·응답 크기 상한·원문·실패·재시도·취소 의미는 바꾸지 않는다.
- 새 키에는 시간 정수·버전·상태만 허용한다. 본문·키·헤더 내용·주소는 기록하지 않는다.
  공개 ModelResult·AttemptMetadata·REST·WS·DB 응답 계약은 확장하지 않는다.

## 이유와 제한

먼저 판정 기준의 모호함을 줄여 기존 형식에서 검토한다. 추가 의미 분류가 필요하다는
증거 없이 출력 스키마·입력 투영·별도 Agent를 동시에 바꾸면 효과의 원인을 분리하기
어렵다. 호출 구간 계측도 속도 개선 자체가 아니며, 추론 토큰과 지연의 상관관계만으로
공급자 내부 처리의 인과관계를 단정하지 않는다.

Luna·추론 강도·출력 상한·timeout·호출 상한·기본 배포 선택을 이 결정으로 바꾸지 않는다.
노출 개발 후보의 검토 비교는 실제 생성·복구·9턴 서비스의 최종 품질이나 holdout 검증을
대신하지 않는다. 실행·검증·남은 범위는 [구현 기록](../implementation.md)에 남긴다.
