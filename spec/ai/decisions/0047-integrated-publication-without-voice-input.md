# 0047. 단일 통합 PR 게시와 미병합 음성 입력의 제외

- 상태: Accepted for publication scope
- 결정일: 2026-11-10
- 근거: 사용자가 기존 PR을 보존한 단일 통합 PR을 요청했고, #185를 제외하는 범위를 선택했다.

## 맥락

#212~#219와 #222~#230은 같은 개발 통합본의 기능별 게시 변경이다.
분리된 PR 사이의 설정·모델·호출·검증 의존성을 통합 게시본에서는 함께 반영한다.
개발 통합본에 결합한 팀원 PR #185의 음성 입력 기반은 이 게시 범위에 포함하지 않는다.

## 결정

1. 최신 develop에서 별도 통합 게시 브랜치를 구성한다. 기존 17개 PR의 브랜치·본문·상태를 보존한다.
2. 17개 PR 내부의 선행 변경과 후속 패치는 실제 코드·설정·테스트·계약으로 연결한다.
   일반 구현과 명세를 나누던 게시 방식은 이번 단일 PR 요청에 한해 통합한다.
3. #185의 음성 버퍼·바이너리 수신·STT 기본 클라이언트·음성 DB 모델·0006 마이그레이션은 복사하지 않는다.
   그 기반이 필요한 이번 작업의 보완과 대응 회귀는 원래 선행 원문에 적용하는 패치로 보존한다.
4. develop에 이미 있는 답변 모드 필드와 FE 음성 UI를 되돌리지 않는다.
   텍스트 면접·Director·질문 복구는 실제 적용 가능한 범위로 연결한다.
   Google TTS 공급자와 예산 관리 코드는 유지하지만, voice 면접 전용 HTTP 합성은 해당 모델 적용을 기다린다.
   음성 입력과 위치 보강의 제공 여부도 별도로 구분한다.
5. 자체 0007 마이그레이션은 실제로 존재하는 0005 면접 기반에서 시작한다.
   0008~0014의 자체 체인은 유지하고, 없는 0006을 가짜 마이그레이션으로 대체하지 않는다.

## 이유와 영향

- 단일 게시 요청을 따르면서 팀원의 미병합 구현을 이번 신규 변경으로 섞지 않는다.
- 초기 설계·과거 결정은 보존한다. 구현·검증 내역은 `spec/ai/implementation.md`에 모은다.
- 음성 입력을 포함한 전체 서비스 완료나 팀의 공통 계약 승인으로 해석하지 않는다.
- #185가 나중에 반영되면 음성 모델·설정·클라이언트와 이 PR의 대기 보완을 함께 재검증해야 한다.
  마이그레이션 0006과 0007이 서로 다른 분기가 되므로, 실제 병합 시 스키마를 보존하는 merge revision을 검토한다.
  다른 PR의 원본 마이그레이션을 임의로 재작성하지 않는다.
- 커밋은 기능·검증·문서별로 나누고 추가·삭제 합계 300줄 이하를 유지한다.
  PR이 하나라는 이유로 모든 변경을 한 커밋으로 합치지 않는다.
