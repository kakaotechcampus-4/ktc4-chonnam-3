# 0025 Director AI·BE 연결 모듈의 신규 게시 경계

- 상태: Proposed
- 날짜: 2026-10-23
- 선행 PR: #82, #102, #114, #119 및 별도 Director 코어 PR

## 맥락

로컬 통합 구현에는 미병합 저장 경계와 L2 분석, 준비·WS 실행이 함께 있다.
신규 연결 모듈을 검토하면서 선행 구현 전체를 중복 게시하지 않아야 한다.

## 결정과 이유

1. 신규 Director·T3 어댑터, 저장 질문·과거 분석의 원문 재검증, 실제 tree 기반 파일 선정·수집과
   그 수집기가 소비하는 8개 상한을 게시한다. 모델 설정·I/O는 기존 공통 gateway를 재사용한다.
2. `load_answer_context`와 반환형, `agent_context`의 현재 질문 로더 보완, L2 어댑터의
   예산·한계·기록 전달 보완은 선행 구현에 붙는 후속이다. 원형 패치를 로컬 보존하고
   선행 반영 후 별도 후속으로 연결한다. 우회 로더나 중복 분석기를 만들지 않는다.
3. 기존 `generate_question`의 base_url 보완도 선행 함수와 함께 보류한다.
   현재 게시 어댑터에는 새 `execute_director`와 필요한 import만 포함한다.
4. 실제 수집기의 구조 상한·부분 성공과 binary/timeout 한계를 검증하는 원래 3사례를 옮긴다.
   준비·WS 실행 테스트는 원본에 보존하고 이 모듈의 통과로 전체 실행 완료를 주장하지 않는다.

## 영향과 후속

### 2026-10-28 기존 생성 경로와 신규 실행 모듈의 분리

- 결정 3은 2026-10-23 원 게시본의 선행 부재를 기록한다. #82가 develop에 반영된 뒤에는
  `backend/app/agents/director/agent.py`를 최신 develop의 `generate_question` 원문으로 유지한다.
- 신규 `execute_director`는 같은 디렉터리의 `runtime_adapter.py`로 분리하고 테스트와 실제
  소비자인 #135의 import를 새 경로로 맞춘다. 두 경로를 합치는 wrapper나 중복 구현은 만들지 않는다.
- 이유는 기존 service의 입력 Contract 경로를 보존하면서 신규 생성·독립 검토의 책임과
  파일 동시 수정 범위를 구분하기 위해서다. 공개 wire 계약과 두 함수의 실행 규칙은 바꾸지 않는다.
- #125 runtime은 미병합 선행으로 남긴다. #133의 미적용 패치는 옛 exact base를 전제하므로
  최신 모듈 배치에 강제 적용하지 않고 일반 코드 반영 전에 실제 대상·필요성을 다시 검토한다.

### 실제 예산의 사전 확인

- BE CallBudget은 remaining_attempts와 terminal_failure를 읽기 전용으로 공개한다.
  종료된 실패는 그대로 반환하고, Director는 Context 허용량과 실제 잔여량의 작은 값을 사용한다.
  생성·독립 검토에 필요한 두 시도가 없으면 새 provider 요청을 만들지 않는다.
- Context 숫자는 실제 호출 예산을 예약하지 않는다. 한 CallBudget은 동일 논리 작업만 소유하며
  다른 job 또는 동시 Director 작업에 재사용하지 않는다. 공통 gateway의 최종 상한 검사는 유지한다.
- 신규 공개 조회를 위해 공통 client의 기존 호출 API·재시도·주소·metadata를 바꾸지 않는다.
  #82의 attempt_sink와 최신 develop의 base_url·시간 상한은 로컬 결합에서 함께 검증한다.

원 게시본 단독에는 #82 저장·도구 모듈과 #125 Director 코어가 없어 Draft로 검토한다.
#102·#114·#119의 최신 develop 병합 여부와 원 게시본의 단독 실행 제한을 구분한다.
공개 API·패키지 의존성·DB 모델·main/worker/WS 등록은 변경하지 않는다.
선행 반영 뒤 보류 Context·L2 보완을 연결하고 고정 SHA·원문·예산 전달을 통합 재검증한다.
원문 수집은 지원 범위의 유한 읽기이며 parser·대형 파일 분할·모든 언어 품질 보장은 아니다.
기존 0012~0015와 0023의 단일 Director 경계를 유지한다.
실제 실행·검증과 보류 범위의 원본은 [구현 기록](../implementation.md)이다.
