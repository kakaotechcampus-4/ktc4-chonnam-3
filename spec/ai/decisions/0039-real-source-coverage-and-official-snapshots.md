# 0039 — 실제 자료의 구조 범위와 공식 원문 재사용

상태: Accepted for local development. 2026-11-08 사용자 요청에 따른 후속 구현 기준이다.
공유 계약 변경의 검토·병합과 사람의 평가 기준 승인을 대신하지 않는다.

## 맥락

앞선 구현은 [0038](0038-final-service-followups.md)의 유한 수집·단일 Director 원칙을 따른다.
실제 공개 서비스와 채용 이미지로 확인하자 구조 수집 예산과 모델 입력 예산이 결합되어 있었다.
작은 기본값만 늘려서는 큰 레포의 구현·테스트가 계속 목록 밖에 남을 수 있다.
분할 원문의 개행 전용 겹침 구간과 제목 앞 bullet도 정상 자료를 거절하는 원인이 된다.

공식 도메인을 제한한 Tavily 검색은 이미 있지만, 미리 수집한 공통 원문 저장소는 별개다.
기존 외부 원문 행에는 사용자·면접 소유권이 있으므로 이를 전역 저장소로 바꾸지 않는다.

## 결정

1. **구조·모델 후보·원문·면접 중 조회의 예산을 분리한다.**
   준비 구조 응답은 2MiB, 전체 수집은 8MiB, 항목은 8192개, 깊이는 12로 제한한다.
   요청 32회, 선정 8파일, 파일 구간 32KiB, 준비 원문 256KiB의 상한을 유지한다.
   실제 모델 원문은 전체 LLM 입력 상한의 절반과 원문 상한 중 작은 값 안에 둔다.
   LLM 전체 입력은 256KiB이며 선정 후보와 응답 schema의 경로 중복도 함께 계산한다.
   후보가 넘치면 실제 모듈에 나눠 제한된 목록을 선정 모델에 전달하고 제외 범위를 표시한다.
   확인한 전체 inventory와 모델에 전달한 목록은 별도로 보존한다.
   inventory의 존재만으로 Evidence나 면접 중 조회 권한을 만들지 않는다.
   진행 중 보완 Tool의 기존 요청·원문·시간 상한은 준비 한도와 별개로 유지한다.

2. **선정 모델 대기와 원문 HTTP 시간을 혼동하지 않는다.**
   원문 HTTP 예산 30초에 실제 선정 작업의 모델 제한을 더해 전체 수집을 제한한다.
   선정 모델 대기는 원문 HTTP 누적 시간을 소비하지 않으며, 지정 경로 재수집에는 더하지 않는다.
   L1 기본 분석은 실측 50초 초과 사례를 반영해 작업별 예시와 로컬 개발 설정에서 180초로 둔다.
   일반 작업 50초·선정/L2 160초·준비 전체 1770초·worker 1800초의 관계를 검증한다.
   L2의 120초 실패와 별도 동일 입력의 약 113초 완료에서 지연 변동을 확인했다.
   최악 계획 1740초가 준비 deadline 1770초 안에 드는 160초로 여유를 늘린다.
   별도 진단의 180초가 필수였거나 timeout 확대만이 성공 원인이라고 단정하지 않는다.
   `LLM_CONNECTION_SLOT=3`은 주소·모델 선택이며 호출 횟수나 동시성 값으로 바꾸지 않는다.

3. **원문과 해석 결과를 구분한다.**
   개행 전용 분할 구간은 빈 SourceDocument로 만들지 않고 원래 줄 범위의 생략을 남긴다.
   유효한 앞뒤 구간의 위치·내용은 그대로 유지한다.
   이미지 공고의 명시 제목 별칭과 bullet만 인식하며 본문 인용·참조를 정규화하지 않는다.
   문장 속 단어로 절을 추정하거나 우대사항을 필수요건으로 승격하지 않는다.
   다른 사이트의 과거 실이미지 검증을 Wanted 이미지 지원의 실검증으로 표현하지 않는다.

4. **공식 catalog와 불변 원문 snapshot을 기존 Tool 앞에 둔다.**
   catalog는 도메인·기술·버전·언어·요청 절과 공개 접근 확인 상태를 버전 관리한다.
   홈페이지의 접근 성공과 본문 추출·요청 절 확인 성공은 구분한다.
   명시적인 유한 수집 CLI로 얻은 원문·추출 줄 위치·원문/절 hash·시각·출처·한계를
   사용자나 면접 FK가 없는 공유 snapshot에 보존하며 기존 원문을 덮어쓰지 않는다.
   질의 관련성과 명시 버전·언어·요청 절을 검사한 자료만 기존 면접별 원문 행으로 복사한다.
   공유 snapshot의 FK를 남기고 면접별 소유권·인용 ID·조회 상태 계약을 유지한다.
   읽지 못한 절, JS 껍데기, 잘린 본문이나 버전이 맞지 않는 자료는 채택하지 않는다.
   같은 공식 도메인이라는 이유로 적합성을 확정하지 않는다.
   부족한 경우에만 기존 Tavily 검색·추출을 사용하고, 미확인 상태는 그대로 전달한다.
   웹 원문은 비신뢰 자료다. 원문의 지시문이나 개인 기여·성과를 사실로 승격하지 않는다.
   수집을 앱 startup에서 자동 실행하거나 별도 자율 분석 Agent를 추가하지 않는다.

## 이유와 대안

실제 Memos 구조는 356770bytes·1500항목, Halo 구조는 1111590bytes·4209항목이었다.
Halo Java 파일은 1386개이며 상당수가 기존 깊이 8 밖에 있다.
이는 이 두 snapshot을 수용하는 설정 근거이며 모든 레포의 완전 분석을 보증하는 값이 아니다.
무제한 다운로드, 모델 입력량의 일괄 확대, 특정 레포의 경로 하드코딩은 채택하지 않는다.
새 검색 서비스·vector DB·자율 Agent 대신 기존 HTTP·Tavily·PostgreSQL·소유권 경로를 재사용한다.
질의의 결정적 관련성 검사에도 의미 해석의 한계가 있으므로 사람의 품질 승인으로 취급하지 않는다.

선정 schema의 큰 경로 enum을 모든 공급자가 같은 크기로 수용한다고 가정하지 않는다.
[공식 OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)는
enum 합계 1000개와 큰 문자열 enum의 별도 문자 상한을 정의한다.
현재 Elice 연결에서의 실호출 관찰은 해당 연결·모델의 지원 범위이며 직접 OpenAI의 보증으로 확대하지 않는다.
공급자를 바꿀 때는 schema 호환 검증과 후보 전달 방식을 다시 확인한다.

## 영향과 이전 결정

0032·0035·0038의 작은 구조 한도를 위 준비 전용 한도로 보완한다.
기존 Evidence 상한·공개 API의 소유권·미검수 평가 상태·원본 보존 원칙은 유지한다.
새 공유 원문 모델·migration은 내부 구현이며, 이미 구현한 GET report의 404 누락과
FE API 설명의 revision·명시 재시도 불일치는 실제 동작에 맞춰 별도 계약 변경으로 정렬한다.

구체적인 파일·실행 수치·통과·실패·미실행과 PR 게시 상태는 [구현 기록](../implementation.md)에 둔다.
이 결정 문서에는 작업 완료 여부를 기록하지 않는다.
