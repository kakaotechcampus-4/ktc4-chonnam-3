# 0051. 질문 낭독의 입력 범위와 발음 보완 복구

- 상태: Accepted for local implementation, 2026-11-11
- 근거: 사용자의 숨김 파일·공백 경로·인용문·추가 주소 형식·라틴 이름·영어 질문 지원 보완 요청
- 관련 결정: [0036](0036-chirp3-service-configuration.md), [0037](0037-tts-complete-history-budget.md), [0045](0045-review-runtime-activation-and-source-recovery.md)
- 구현·검증 기록: [단일 구현 기록](../implementation.md#question-speech-v4-20261111)

## 결정

1. 질문 원문과 음성용 낭독문을 분리한다. 숨김 파일, 숫자로 시작하는 확장자, 파일 문맥의 단독 파일명, 인용된 공백 경로, scheme 없는 `www.` 주소와 한글 경로를 구조적으로 처리한다. `www.`에 존재하지 않는 HTTP scheme을 발명하지 않으며, 한글 이름의 마지막 음절을 조사로 추정해 삭제하지 않는다.
2. 악센트가 있는 라틴 이름은 한 단어로 추출하고 발음 후보에서 NFC로 정규화한다. 라틴 이름과 한국어 이름을 구분해 한국어는 로컬에서 읽는다. 숫자·버전·쿼리의 실제 값·퍼센트 인코딩은 원문의 구조에 따라 처리하고 이름 발음 모델에 섞지 않는다.
3. 안내 문장을 감싼 인용부호와 내부 쉼표는 자연스러운 낭독을 적용한다. 문장 안에 주소·파일이 있어도 각 구성요소를 보완한다. 문자열·기호·표기 자체의 비교 질문과 코드·명령·자격증명 가능성이 있는 원문에는 보수적인 보존 정책을 유지한다. 등록된 `.NET` 같은 기술명은 같은 범위의 파일 해석보다 우선한다.
4. 전체 영어 질문도 제한된 이름·구절로 분리해 발음 보완 대상으로 삼는다. 의미 번역이나 질문 재작성은 허용하지 않는다. 기존 `low`, 최대 5초, 한 번의 시도와 입력·출력 상한을 유지한다. 한글 형식 검사만으로 발음 정답을 보장한다고 해석하지 않는다.
5. 실제 모델 시도의 실패·시간 초과·잘못된 출력으로 기본 음성을 만든 경우, 주 캐시의 재사용 시간은 기존 전체 TTL과 60초 중 짧은 값으로 둔다. 같은 캐시 식별자의 별도 보관 키에는 최종 낭독문 해시와 MP3를 전체 TTL 동안 보존한다. 보관 키를 먼저 기록하고 주 캐시를 마무리하는 과정을 기존의 유한한 취소 보호 안에서 수행한다.
6. 재사용 시간이 지난 후 같은 질문을 다시 요청할 때만 기존 단일 실행 잠금 안에서 모델을 한 번 더 시도한다. 계속 실패하거나 최종 문장이 같으면 저장된 MP3를 재사용한다. 더 나은 문장이 생기면 새 음성을 한 번 합성해 정상 TTL로 전환한다. 개선 합성의 예산 부족·공급자 오류에는 현재 질문의 보관 음성이 있으면 재사용하고 짧은 재사용 시간을 유지한다. 백그라운드 무한 재시도는 만들지 않는다.
7. 같은 기본 음성을 재생하는 데 새 Google 합성이나 문자 예약을 만들지 않는다. 실제 개선 합성만 새 문자를 예약하고 이미 사용하거나 결과가 불확실한 사용량은 환불하지 않는다. 새 질문인지와 소유권을 합성·캐시 반환 전후에 확인하는 기존 경계를 유지한다.
8. 변환 규칙은 `question-speech.v4`로 구분해 이전 정책의 MP3가 새 입력 지원을 가리지 않게 한다. 공개 REST·WebSocket·DB 질문 원문과 환경 변수 계약은 유지한다. 프롬프트가 없거나 모델 설정이 맞지 않는 상태는 기존 로컬 처리와 캐시 식별자 변경으로 구분한다.

## 이유와 영향

단순히 실패 음성의 TTL만 줄이면 장애 중 같은 문장을 반복 합성해 비용이 증가한다. 기본 음성 보관과 발음 재시도 시점을 분리해 이를 방지한다. 영구 발음 사전은 이번 범용 입력 지원과 별개이며 문맥별 발음 차이와 오발음의 영구 저장을 피하기 위해 자동 생성하지 않는다.

이 결정은 로컬 구현의 범위다. 사람의 청취 평가와 실제 운영 반영은 해당 환경에서 별도로 확인한다. 0037의 확인 근거에 따른 예산 관리와 0045의 취소·정산 보호를 대체하지 않는다.
