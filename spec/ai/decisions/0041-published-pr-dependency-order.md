# 0041 — 게시 PR의 공통 기반과 통합 검사 순서

상태: Accepted. 2026-11-08 게시된 #212~#219의 후속 정리에 적용한다.

## 맥락

기능별로 나눈 PR 사이에서 모델 export·마이그레이션·프롬프트·검색 클라이언트를
서로 앞뒤로 참조하고 있었다. 일부 공통 검사도 뒤 단계의 REST·WebSocket이나
평가 데이터가 있어야 실행되는 통합 검사였다. 기능 전체를 검증한 결과와 각
게시본을 develop에 단독으로 적용한 결과를 구분할 필요가 있다.

## 결정

1. 기존 PR 번호와 develop 기준을 유지한다. 원본 HEAD와 통합본을 보존하고
   후속 커밋을 추가한다. 다른 PR의 커밋이나 선행 구현을 복사하지 않는다.
2. 공통 계약·모델·0007~0013 마이그레이션·런타임 프롬프트·Tavily 클라이언트와
   준비 lease·이벤트 공통 변경은 #213에 배치한다. 하위 기능별 코드와 검사는
   해당 기능 PR에 두며 같은 신규 변경을 여러 PR에 중복 게시하지 않는다.
3. 계약(#212), 공통 기반(#213), 문서·JD(#217), Director·레포(#216),
   리포트·프로필(#218), 평가 실행(#214), 평가 데이터·CI(#215),
   음성·FE와 최종 연결(#219) 순으로 검토·통합한다. 이 순서는 필요한 외부
   선행 PR까지 반영한 환경을 전제로 하며 즉시 병합 가능함을 뜻하지 않는다.
4. 기능별 테스트의 단언·입력과 제품 동작을 보존한다. REST·WebSocket 등
   뒤 단계가 필요한 검사는 그 단계로 소유권을 옮긴다. 준비 재시도 REST
   검사 한 개는 준비 단위 검사에서 WebSocket 통합 검사 파일로 옮기고
   기존 fixture·도우미·검사 본문을 그대로 재사용한다.
5. 선행 구현과 수정 구간이 겹치는 19개 후속 패치는 실행 코드와 구분한다.
   선행 PR 반영 후 적용·재기준화·재검증해야 하며, 파일이 게시됐다는 이유로
   실행 경로까지 연결됐다고 보고하지 않는다. 외부 선행이 남은 PR은 Draft다.
6. 게시 이후 별도로 작업한 45개 변경은 이번 정리에서 제외한다. 공급자
   실제 호출과 사람 평가는 실행하지 않으며, 새 자동 검증과 과거 검증을
   구분해 [구현 기록](../implementation.md)과 PR 본문에 남긴다.

## 영향

공통 기반이 소비 기능보다 먼저 준비되며 내부 PR 간 의존 순서가 명시된다.
테스트와 제품 기능의 합집합은 유지된다. 각 게시본의 단독 CI 실패는 외부
선행 미반영·비활성 패치와 구분해 확인하고, 최종 병합 전 통합 검증을 반복한다.
기존 설계·검증 기준 문서에 구현 완료 표시를 추가하지 않는다.
