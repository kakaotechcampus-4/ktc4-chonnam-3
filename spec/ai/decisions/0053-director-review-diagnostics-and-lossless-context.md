# 0053. Director 검토 진단과 원문 손실 없는 평가 문맥

## 상태

Accepted for local development and evaluation, 2026-11-11.

[0052](0052-director-problem-oriented-evaluation.md)의 평가·질문 정책을 보완한다.
서비스 활성화·게시·사람 검수 완료를 뜻하지 않는다.

## 배경

모델의 첫 검토가 후보를 반려하면 분류 코드만으로는 어떤 조건이 충돌했는지 알기 어렵다.
나중에 같은 검토를 다시 호출해 얻은 이유를 최초 판단의 이유로 소급할 수도 없다.
원문을 보존하더라도 Plan과 Review의 같은 입력을 평가 문맥에 중복 배치하면 바이트
상한 때문에 평가자가 실제 근거를 받지 못할 수 있다.

## 결정

검증된 Review의 다섯 boolean과 짧은 판단 요약, 코드가 계산한 복구 분류를 별도 사적
`director-diagnostics.v2`로 기록한다. 당시 요청 payload·프롬프트 정책·실제 응답 모델·
원응답 바이트 지문·JSON 내용 지문·시도 위치에 결합하고 성공·실패·취소·재판정에서도
보존한다. 판단 내용도 실제 응답에서 계산한 JSON 내용 지문과 같아야 한다. 기존 검증기를
통과하지 않은 응답을 관찰자가 승인하거나 해석하지 않는다. 모델의 자기 승인은 품질
판정 근거가 아니며 이 진단은 Judge 입력·공개 응답·Langfuse 전송 자료에 넣지 않는다.
과거 v1은 원형과 기존 바이트 결합을 유지해 읽되 판단 내용의 독립 결합이 없는 형식이다.
v1을 v2와 같은 보증으로 부르거나 원본 기록의 버전을 소급 변경하지 않는다.

새 `director-model-sources.v3`의 원본 스냅샷에는 실제 Plan·Review 입력 두 개를 그대로
보존한다. 파생 평가 문맥에서만 JSON 값의 내용 지문이 같은 공통 top-level payload 필드를
한 번 저장하고 각 요청은 공통 자료 참조와 차이, 원래 payload 지문을 가진다. Python의
`True == 1` 비교로 서로 다른 JSON 값을 합치지 않는다. 합집합으로 실제 입력을 정확히
복원할 수 있어야 한다. 정책 본문도 지문으로 공유하되 실제 버전·원문을 보존한다.

v1/v2를 읽는 방식과 이미 저장한 판정의 문맥 지문은 유지한다. 과거 원본을 새 형식으로
덮어쓰지 않는다. 필요한 경우 별도 파생 v3 packet, 원본 지문과 변환 근거를 만들고 새로운
판정을 그 packet에 결합한다. 중복 제거 후에도 예산을 넘는 자료는 누락을 표시하며 읽지
않은 범위를 읽었다고 판정하지 않는다.

v11 후보 질문 정책은 실제 질문과 계약의 확인 범위를 맞춘다. 필수 채점 항목을 질문에 숨기지
않고, 프로젝트→JD 연결도 질문·필수 확인점·평가 범위에 같은 목적으로 나타낸다.
대상·제약·확인 결과의 실제 차이가 없는 설명 방식이나 Persona 변경을 새 질문 목적의
근거로 삼지 않는다. 원문 조건의 값·비교·부정과 가정·실제 구현을 구분한다. 후보 작성·
실행 검증과 기본값 변경을 분리한다. 일부 실패 재현의 개선만으로 지연·첫 시도 성공의
회귀를 상쇄했다고 판단하지 않으며 전환 근거가 부족하면 기존 v10 기본값을 유지한다.

첫 시도 반려와 최종 서비스 실패를 별도로 집계한다. 복구 실행은 원래 실패를 바꾸지 않고
새 시도와 예산으로 기록한다. 모델 설정이 실행 중 달라지면 임의로 섞지 않는다. 사적 검증
환경에서는 당시 캡처한 유효 task별 설정을 명시적으로 선택하고 현재값과의 차이를 남긴다.
이는 운영 서비스에 자동 설정 덮어쓰기나 무한 재시도를 추가하는 결정이 아니다.

## 대안과 영향

- 원문을 잘라 넣거나 평가 상한을 늘리는 대신 같은 자료의 중복 표현을 먼저 제거한다.
- 모델 재호출로 과거 이유를 추정하는 대신 검증된 당시 판단만 진단으로 남긴다.
- 원문 검색 누락과 질문·계약 불일치는 구분한다. 검색·임베딩·Lang 계열의 도입은 0052의
  실제 문제·대조 기준을 계속 따르며, 이 결정이 도입을 금지하거나 요구하지 않는다.
- 공개 REST·WS 필드, DB 컬럼, HR 1·기술 6·도메인 2의 배분은 바꾸지 않는다.
- 실행·Codex 판정·사람 검수·운영 품질을 구분한다. 노출된 실패 재현·pilot 자료를 독립
  holdout으로 부르지 않으며, 공식 예제·템플릿 검증을 다양한 운영 레포의 검증으로 넓히지 않는다.

실제 변경·명령·검증 결과와 한계는 [구현 기록](../implementation.md)에서 관리한다.
