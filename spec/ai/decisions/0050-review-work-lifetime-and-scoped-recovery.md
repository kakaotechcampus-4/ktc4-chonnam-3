# 0050 — 면접 작업 수명과 리뷰 결과의 제한적 복구

- 상태: Accepted for implementation and publication scope
- 날짜: 2026-11-10
- 선행: [0049](0049-integrated-review-runtime-consistency.md)

## 맥락

면접의 작업 표식이 모델 재시도·외부 조회·자동 질문 재생성보다 먼저 만료되면
재접속은 정상 실행을 실패로 판단한다. 문서 재추출은 문장이 같아도 유형·태그·원문
위치가 바뀔 수 있다. 프로필은 검증한 생성 결과를 보관한 뒤 DB 저장에서만 실패할 수 있다.
기존 성공 캐시와 영구 실패 요청은 코드 수정만으로 자동 재실행되지 않는다.

## 결정

1. 면접 작업은 소켓과 별개로 자기 nonce의 표식만 갱신한다. 재접속이 소켓 소유자를
   교체해도 수락한 답변 처리는 유지한다. 전체 실행 기한은 설정된 모델 시도·재시도 대기,
   근거·외부 조회·최초 질문 및 한 번의 자동 rewrite 예산에서 계산한다. 기존 30초 임대
   단위는 갱신·로컬 저장 여유에 사용한다. 기한은 무한히 연장하지 않는다.
2. 자동 rewrite의 실행권·DB pending·외부 조회 예약을 정리한 뒤 작업 표식을 해제한다.
   WS의 부모 작업만 취소하고 shield된 자식을 남기지 않는다. 수동 HTTP 재시도의 기존
   연결 취소 차단은 보존한다. 새로운 소유자의 표식은 갱신하거나 삭제하지 않는다.
3. 문서 Claim은 문서·버전·문장·문단과 유형·태그·원문·위치가 모두 같을 때만 재사용한다.
   달라진 결과는 새 행을 활성화한다. 과거 질문과 대조 결과가 참조하는 행은 덮어쓰지 않는다.
4. 프로필의 일시적 DB 오류는 드라이버 코드·연결 무효화 상태로 판정한다. 검증된 생성
   결과를 보존하며 기존 최대 5회·24시간·backoff 안에서 재전달한다. 영구 SQL·모델·설정
   오류를 일괄 재시도하지 않는다. 재예약 저장도 실패하면 임대 만료 복구에 맡긴다.
5. 실제 부모 관계가 있는 질문의 위치는 원래 main까지 따라 계산하고 REST·WS·리포트가
   같은 함수를 사용한다. 관계 필드가 없던 기록의 호환은 구분해 유지한다.
6. 이미지별 다운로드는 redirect 전체를 포함한 절대 기한을 갖는다. Vision에는 별도 호출
   제한을 적용하고 전체 수집 기한도 유지한다. 실패·취소 전 소비 바이트와 기존 원문을 보존한다.
7. 지식 설정과 공식 자료 수집은 동일한 URL query 거절 정책을 사용한다. 설정·실제 bind의
   대상과 접속 후 DB 이름을 확인한다. Judge의 잘못된 반환값은 구조화된 기술 실패로 남기고
   CLI 실패로 반영한다. 품질 판정이나 사람 검수 대기를 기술 실패와 혼동하지 않는다.

## 기존 데이터 복구의 경계

- 기본은 dry-run이다. non-production 환경·명시한 DB·한 사용자·문서/요청 ID·담당자·사유를
  요구한다. 한 번의 대상 수는 기존 복구 페이지 상한을 넘기지 않는다.
- apply는 검토한 상태의 SHA-256이 일치하고 쓰기 전 감사 기록이 확정된 경우에만 허용한다.
  원문·Claim·리포트·기존 대조 이력은 삭제하지 않는다. 살아 있는 예약과 종료되지 않은 면접의
  문서는 변경하지 않는다. 준비 실패도 첫 질문을 재사용해 재개할 수 있으므로 포함한다.
  문서의 활성 캐시만 무효화해 다음 정상 준비 경로에서 다시 추출한다.
- 프로필은 확인된 internal error의 실패 요청 중 현재 소유 리포트 revision과 잔여 회차·만료가
  유효한 대상만 pending으로 되돌린다. 회차·만료·검증 생성 결과는 초기화하지 않는다.
- 복구 명령 자체는 모델·큐를 호출하지 않는다. 이후 정상 작업에서 생성 결과가 이미 삭제된
  요청은 추가 모델 호출이 필요할 수 있다. 실패 요청 전체나 문서 전체를 자동 재개하지 않는다.
- 감사는 대상 식별자·상태·지문을 기록한다. 원문, 생성 문장, 비밀 설정은 출력하지 않는다.
  applying 뒤 결과 기록이 없으면 DB 상태를 먼저 확인하며 이전 사전 상태로 무조건 재실행하지 않는다.

## 영향과 검증 기준

공개 API와 DB 스키마는 유지한다. 선행 문서·결정·평가 snapshot은 보존한다. 질문 수·개인 기여
확정 정책·공급자 재시도 횟수를 확대하지 않는다. 재접속·기한·취소 정리, Claim 이력, 프로필의
한 번 생성 후 저장 복구, 실제 부모의 세 응답 일치, 이미지 기한·소비량, 대상 DB 거절,
Judge 기술 실패 및 복구 대상의 원자적 변경을 자동 검증한다. 실행 결과는
[구현 기록](../implementation.md)에만 모은다.
