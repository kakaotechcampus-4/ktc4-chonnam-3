# 0013 JD 섹션 제목 제외와 기존 캐시의 새 버전 생성

- 상태: Proposed
- 날짜: 2026-11-09
- 관련 PR: 병합된 [#15](https://github.com/kakaotechcampus-4/ktc4-chonnam-3/pull/15)의 후속 수정
- 검토자: 후속 코드 리뷰에서 확인 예정

## 맥락

공고 본문의 독립된 `필수 역량`, `주요 역할` 같은 제목은 지원자에게 요구하는 내용이 아니다.
이를 요구사항 행으로 저장하면 총 20개 상한을 소모해 실제 문장이 누락될 수 있다.
추출기만 바꾸면 7일 이내의 기존 성공 캐시는 추출기를 거치지 않고 계속 재사용된다.
기존 요구사항을 직접 삭제하면 과거 면접 턴이 참조하는 당시 근거가 바뀐다.

## 결정

1. 공고의 세 그룹에 속한 문단 전체가 알려진 한국어 섹션 제목과 일치할 때만 제외한다.
   비교용 사본에서 목록 기호, Markdown 제목·강조, 번호, 짝이 맞는 괄호, 끝 콜론과 공백을
   정리한다. 문장 안의 제목 단어, 유사 단어, 짝이 맞지 않는 장식은 삭제하지 않는다.
   제목 목록에 없는 표현을 의미 추론으로 제거하지 않는다.
2. 제목 제외 후 기존 개수 배분을 적용한다. `required`, `preferred`, `responsibility`의
   구분과 그룹 내 순서, `source_field`, 공고 기술 태그를 유지한다.
   기존 목록 기호 제거 외에는 실질 문구를 다시 쓰지 않는다. 원문 `PostingContent`는 변경하지 않는다.
   제목밖에 남지 않으면 기존 `jd_extraction_failed` 오류로 처리한다.
3. 추출과 캐시 검사에서 같은 제목 판별 함수를 사용한다. 정상이며 유효기간 안의 캐시는
   기존처럼 HTTP 호출 없이 재사용한다. 제목 행이 있는 캐시는 유효기간 안이어도 원문을
   재수집한다. URL별 저장 잠금 안에서 다시 검사해 동시에 생성된 정상 버전을 재사용한다.
4. 정제된 요구사항이 기존 저장 행과 다르면 기존 공고 버전 저장 절차로 새 공고와 요구사항
   ID를 생성한다. 기존 행·원문·분석 실행·면접·턴의 참조는 수정하거나 삭제하지 않는다.
   재수집이나 추출이 실패해도 기존 성공 자료를 보존한다. 잘못된 캐시를 성공 결과로 돌려주지 않는다.

## 이유

제목의 정확한 일치만 검사하면 요구사항 문장을 임의로 요약하거나 분류를 바꾸지 않으면서
확인된 오류를 제거할 수 있다. 별도 모델 호출이나 의존성이 필요하지 않다.
캐시 검사를 수집 전과 저장 잠금 안에서 공유하면 기존 URL 동시성 처리와 버전 보존을 재사용한다.

- 모든 제목 유사 문구 제거: 실제 요구 문장까지 삭제할 수 있어 채택하지 않는다.
- 기존 행 삭제·수정 또는 참조 일괄 이동: 당시 면접 근거를 바꾸므로 채택하지 않는다.
- 전체 캐시 무효화: 정상 공고도 재수집하므로 채택하지 않는다.
- DB 컬럼·마이그레이션 추가: 현재 행에서 판별할 수 있어 필요하지 않다.

## 영향과 검증 기준

공개 API·스키마·에러 코드·DB 구조는 유지한다. 새 분석의 공고 조회에서만 정제 버전을
받으며, 이미 공고 ID가 고정된 분석과 면접은 당시 자료를 유지한다.
추출기를 되돌려도 새 버전을 삭제하거나 과거 참조를 옮기지 않는다.

제목 장식·문장 보존·20개 배분·제목 전용 입력을 단위 검사한다. PostgreSQL에서 정상 캐시,
오류 캐시의 새 ID, 기존 참조 보존, 동시 갱신, 수집·추출 실패를 검사한다.
실제 실행 결과와 미검증 범위는 [구현 기록](../../ai/implementation.md#jd-heading-fix-20261109)에 둔다.
