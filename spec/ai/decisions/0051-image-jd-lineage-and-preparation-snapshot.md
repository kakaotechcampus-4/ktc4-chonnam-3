# 0051 — 이미지 JD의 전달 검증과 준비 스냅샷 보존

- 상태: Accepted for local implementation
- 날짜: 2026-11-10
- 관련: #210, [0038](0038-final-service-followups.md), [0049](0049-integrated-review-runtime-consistency.md)

## 맥락

이미지 전사·요구사항 저장, Director 입력, 리포트 출처 복원은 개별 검사가 있지만 같은
공고·면접으로 이어 실행한 근거는 별도로 필요하다. 현재 실제 URL 수집 범위는 Wanted이며,
다른 사이트에서 확보한 실제 이미지의 캡처 재생을 해당 사이트의 제품 지원으로 볼 수 없다.

공개 면접 생성 API부터 준비를 연결하면 선택 레포의 SHA·primary가 처음에는 미설정이다.
앱 세션은 `autoflush=False`다. 준비 스냅샷을 메모리에 설정한 뒤 checkpoint의
`populate_existing` 조회를 실행하면 미저장 값이 사라져 정상 선택을 변경된 입력으로 판정한다.

## 결정

1. 준비 `_snapshot`의 선택 SHA·primary 변경을 같은 transaction에서 명시적으로 flush한 뒤
   checkpoint를 읽는다. 전역 autoflush는 변경하지 않는다. 기존 입력 잠금·권한·고정 SHA·
   checkpoint 재사용 검사는 유지하며, 이후 검증 실패 시 전체 transaction을 rollback한다.
2. 통합 회귀는 공개 생성 경로의 미설정 선택 상태에서 시작하고 정상 준비·9턴·리포트 작업을
   실행한다. DB 상태를 완료로 바꾸거나 선택 스냅샷을 미리 채워 준비 실패를 감추지 않는다.
   외부 HTTP/모델 응답 경계만 대역으로 제어하며 실제 Context·질문 검증·저장은 사용한다.
3. 실제 이미지·전사·과거 모델 출력은 원본 지문으로 보존한다. 현재 parser의 파생 결과와
   과거 결과를 구분하고, 설명뿐인 시각 영역·OCR 보정 추정·없는 필수요건을 원문으로 만들지 않는다.
4. 다른 사이트 자료는 수집 이후 캡처 재생으로 표시한다. 지원 형식의 합성 transport를 쓰면
   원본 URL·해시·블록 ID와 시험용 주소의 대응을 명시한다. URL·DB source 허용 범위를 완화하거나
   Wanted 실제 공고·타 사이트 URL 지원으로 보고하지 않는다.
5. 리포트는 실제 질문한 JD의 원문만 내부 `source_notes`로 전달한다. 공고의 요구사항은 지원자의
   구현·개인 기여를 입증하는 코드 Evidence가 아니다. 원문 부재·해시 불일치·prefix 범위는 한계로
   유지하며, 공개 API에 검증 전용 출처 필드를 추가하지 않는다.
6. 자동 회귀의 의도된 질문 응답과 Luna의 실제 선택은 별도로 기록한다. 실호출에서 해당 JD를
   질문하지 않으면 미관찰이며, 사후 ID 삽입·검수 생략·반복 실행으로 성공을 만들지 않는다.

## 영향과 검증 기준

공개 API·DB 스키마·프롬프트·9턴 정책은 유지한다. 선택 반영은 기존 transaction 안에서만
확정되며 과거 면접·공고 원문·실패 결과를 변경하지 않는다. 새 면접 스냅샷의 별도 세션 재조회,
동일 JD의 Context·질문·리포트 모델 입력 연결, 미질문·원문 손상·부분 구간·캐시·소유권을 검사한다.
출처 전달을 제거한 변이 조건에서도 통합 회귀가 실패하는지 확인한다.

실제 자료 재생·모의 외부 응답·실제 PostgreSQL/Redis·제한된 실제 Luna 호출을 구분한다.
사람 품질 승인·새 OCR 정확도·운영 배포는 이 결정으로 완료 처리하지 않는다.
실행 결과와 남은 한계는 [구현 기록](../implementation.md)에 모은다.
