# 0019 Sprint 1 개인 역할 요약의 기존 계획 복원

- 상태: Accepted — 개인 역할 요약 보류 철회, 기존 구조 유지
- 날짜: 2026-09-22
- 결정자: 현재 사용자
- 관련 PR: 없음
- 직접 승인: 기존 저장 항목·API·화면·갱신 흐름을 유지하고 원래 계획한 LLM 역할 요약을 구현 대상에 다시 포함한다는 설명에 사용자가 “그럼 그렇게 정하자.”라고 승인함.

## 이유와 범위

기존 `backend/app/llm_tasks/profile_summary.py` 골격은 `user_profile_summaries.role_summary`를 LLM으로 생성하도록 설명했다. 실제 생성 기능은 미구현이다. 0006의 프로필 LLM 비호출과 0016의 역할 요약 보류는 구현량을 줄이는 선택이었으며, 기술적으로 반드시 필요한 제한은 아니었다. 사용자는 기존 기능을 유지하는 방향으로 이 부분을 되돌리기로 했다.

이번 결정은 개인 역할 요약만 복원한다. 0016의 저장소 중복 제거·언어 비율 계산, 문서 Claim의 Sprint 2 범위, 그 밖의 확정·보류 사항은 유지한다.

## 결정

1. Sprint 1에서 개인 역할 요약을 제공한다. 기존 `profile_summary_v1`의 LLM 요약을 구현 대상에 포함하고, 모든 응답을 “개인 역할 요약은 아직 제공하지 않습니다.”로 대체하는 지침은 철회한다.
2. 기존 `profile_summary(user_id)`, `user_profile_summaries.role_summary`, 공개 `roleSummary` 문자열과 홈 화면의 역할 문단을 유지한다. 새 job·테이블·컬럼·API 필드·화면을 요구하지 않는다.
3. 기존 `report_generate` 성공 후 프로필 갱신 흐름을 유지한다. 리포트 응답은 프로필 완료를 기다리지 않으며 프로필 실패가 성공한 리포트를 실패로 되돌리지 않는다. 기존 실패 분리·직전 성공 요약 보존·Sprint 2 복구 범위를 유지한다.
4. 저장소 수·언어 비율·프로젝트 유형은 기존 확정 자료로 집계한다. 언어 비율은 0016의 저장소별 동일 비중 평균을 유지하며 모델이 통계·수치를 계산하거나 바꾸게 하지 않는다. LLM은 개인 역할의 자연어 요약에 사용한다.
5. 요약은 기존 자료에서 근거를 확인할 수 있는 역할을 대상으로 한다. README의 프로젝트 설명이나 commit 수만으로 개인 기여를 단정하지 않고, 사용자 진술과 확인된 사실을 구분한다. 자료 부족·호출 실패를 추측한 역할 문장으로 채우지 않는다. 실제 입력 자료 선택·프롬프트·출력 검증은 기존 저장 자료와 호출 경계에 맞춰 구현한다.
6. 모델 선택과 호출·검증·기록 책임은 0011 및 기존 공통 LLM 정책을 따른다. 새 모델·공급자·별도 실행 경로를 추가하지 않는다.

## 반영과 검증

- AI·BE·FE의 역할 요약 설명과 검수 기준, 관련 골격의 주석을 이 결정에 맞춘다. 옛 결정 본문은 이력으로 보존하고 대체 범위를 표시한다.
- 실제 생성·호출·저장·화면 연결은 구현 작업이다. 문서 반영을 기능 구현 완료로 표시하지 않는다.
- 구현 시 기존 집계 결과·공개 필드·프로필 갱신 및 실패 분리를 유지하는지, 역할 요약이 입력 근거를 넘는 개인 기여를 만들지 않는지 검증한다.
- 이번 반영은 문서·주석에 한정한다. 실행 로직·DB migration·API 스키마·화면 코드·mock 데이터는 변경하지 않는다.
