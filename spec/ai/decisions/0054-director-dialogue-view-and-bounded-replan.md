# 0054. 전체 답변의 인접 배치와 제한된 자동 재계획

## 상태

Accepted for local experimental development and evaluation, 2026-11-11.

사용자가 Director 개선을 계속하도록 요청한 범위의 로컬 후보 결정이다. 기본 프롬프트 전환과
운영 활성화는 대조 검증 뒤에 별도로 판단한다. 0050의 기존 자동 rewrite 정책을 보존하고,
0052·0053의 평가·원문 보존 경계에 새 후보 v12의 동작만 추가한다.

## 배경

실제 반복 사례에는 원문 답변이 제공됐지만 새 질문 검토가 이미 답한 범위를 놓쳤다.
특히 질문 밖에 덧붙인 미확인 설명은 T3의 covered_points 인용에 없을 수 있다.
과거 계약은 HistoryTurn 필드가 아니므로 이를 추측한 목적 요약으로 대신하면 안 된다.
또 기존 자동 복구는 rewrite에 한정되어, 안전한 대안이 있는 replan도 수동 재시도가 필요하다.

## 결정

v12 모델 입력에서만 과거 문답과 같은 turn_id의 검증된 분석을 `answered_turns`에 붙인다.
질문·전체 답변·순서·ID와 분석의 주장 상태·기여 범위·한계를 그대로 보존한다. 계약 목적을
추측 생성하거나 분석에 인용되지 않은 발언을 버리지 않는다. 분석은 관찰의 해석이며 구현
사실·개인 기여·역량의 증거로 승격하지 않는다. 현재 턴은 current_answer/answer_analysis에
한 번만 두고 두 모델 시도에 같은 자료를 제공한다. v1~v11 입력은 바꾸지 않는다.

Plan과 Review는 후보가 요구하는 설명·판단·검증 목적을 모든 과거 답변과 대조한다.
같은 코드에서도 실제 새 조건이나 결정이 있으면 허용한다. Persona·topic·전달 대상·표현만
바꾼 질문은 새 목적이 아니다. 새 조건의 이름을 붙였다는 사실만으로 새 추론을 요구한다고
판단하지 않는다. 질문에서 실제 묻지 않은 내용을 필수 채점 대상으로 숨기지 않는다.

후보 프롬프트는 기존 안전·근거·질문 관계 정책을 유지하면서 간결하게 쓴다. 단계 수와
모델은 유지하며 추가 요약·Judge 호출을 넣지 않는다. 인용 참조 풀이나 임베딩 도입은
이번 후보에 섞지 않는다. 같은 자료에 대한 필요성이 입증된 경우에만 별도 비교한다.

답변 뒤의 자동 복구는 v12 capability가 있는 최초 실패에 한해 안전한 replan을 허용한다.
검증된 두 원시 시도에서 feedback을 복원할 수 있고, 현재 소유권·질문 번호·원문·답변·
현재/과거 분석·프롬프트가 최초 생성과 같아야 한다. 최초 생성 시 전체 typed 입력과
프롬프트의 지문을 context_state에 기록하고 예약·결과 확정 시 다시 대조한다. 지문이나
feedback이 없거나 정책·자료가 달라졌으면 자동 실행하지 않는다. no_valid_candidate도
자동 재생성하지 않는다. 기존 실패를 새 성공으로 바꿔 쓰지 않는다.

rewrite와 replan은 같은 target의 기존 auto 슬롯 하나를 공유한다. 모델 두 시도의 새 라운드
최대 한 번이며 새 자동 슬롯·수동 회수·공급자 재시도·작업 기한을 늘리지 않는다. 기존
`automatic-rewrite` UUID namespace는 기존 슬롯의 불투명 식별자로 보존하고 실제 복구
분류는 별도 recovery_kind로 기록한다. 과거 프롬프트 실패를 현재 v12라는 이유로 자동
재계획하지 않는다. 첫 질문 준비의 자동 재계획은 이 결정의 범위 밖이다.

평가 bridge는 실제 실행과 동일한 prior_analyses/recovery_feedback 입력을 명시적으로
받을 수 있다. 실제 모델 표시 입력이 동결 원본과 같은지 먼저 검증하며 이 자료를 지워서
재현했다고 주장하지 않는다. 과거 결과와 새 후보의 결과·기준·설정·비용은 분리한다.

## 영향과 검증 기준

공개 REST·WS·DB 스키마, 9턴·HR1/기술6/도메인2·점수 정책은 유지한다. 단일 Director와
기존 Model Gateway·Controller를 재사용한다. 메모리의 전체 원문 보존과 legacy 입력 지문,
새 조건의 허용/같은 설명의 반복 거절, 소유권·자료·분석·정책 변경 거절, 한 슬롯·취소·
재전송·비활성 버전·안전 대안 없음과 실제 Luna 대조를 검증한다. 모델 반복 오류를 단순
문자열 유사도나 코드 경로 하드코딩으로 판정하지 않는다. 실제 결과와 실패는 기존
[구현 기록](../implementation.md)에만 남긴다.
