# 0027 미병합 선행 파일의 신규 Director 보완을 후속 패치로 분리

- 상태: Proposed
- 날짜: 2026-10-25
- 선행: #82, #114, #119, #126
- 관련 자료: `backend/patches/director-followups/`

## 맥락

사용자는 현재 미게시 신규 변경을 모두 검토하도록 게시하되, develop을 기준으로 미병합 선행과
기게시 코드를 복사하지 않도록 요청했다. 대상 Context 파일은 develop에 없고 L2 어댑터는 골격이다.
따라서 원본 파일 전체를 추가하면 이번 수정 외의 선행 구현이 함께 게시된다.

## 결정과 이유

- 신규 수정 구간만 미적용 unified diff와 base/result blob·패치 해시 manifest로 보존한다.
  이 PR은 후속 변경의 검토 자료이며 일반 Python 반영이나 기능 활성화를 수행하지 않는다.
- 실행·빌드·설치·CI에서 자동 적용하지 않는다. 선행 반영 후 정확한 base 일치와 적용 검사를
  통과한 별도 코드 변경으로 반영하고 관련 회귀·통합 검증을 다시 수행한다.
- 기존 질문 복원·과거 분석 함수, L2 본체, DB 모델·migration·의존성은 복사하지 않는다.
- 원본과 제외한 seed 검증은 기존 백업에 보존한다. seed 문제는 #131의 별도 범위다.

## 영향과 후속

공개 API와 현재 실행 경로는 변경하지 않는다. Context·L2·프록시 후속 구현의 적용은 미완료이며
패치만 병합한 상태를 구현 완료·병합 가능한 면접 서비스로 보고하지 않는다.
선행 결과가 manifest의 base와 달라지면 수정 구간을 재검토하고 해시·검증을 갱신한다.
ADR 0025가 보류했던 연결 보완을 검토 가능한 형식으로 공개하며 그 적용 조건을 대체하지 않는다.

## 2026-10-28 적용 대상과 실행 선행의 구분

- 위 맥락은 원 게시 당시의 분리 이유로 보존한다. 현행 적용 대상은 manifest의
  `application_required`로 명시하며, 선행 코드에서 이미 충족한 변경은 이력으로 보관한다.
- 패치 4의 base URL 보완은 #82에 포함되므로 현재 적용 대상에서 제외한다. 기존 파일과
  base/result·해시·옛 선행 참조는 보존하며 빈 패치나 옛 통합 파일의 재도입으로 대체하지 않는다.
- 적용 전에 파일 해시뿐 아니라 소비 API와 실제 호출 기록·공유 예산·취소 동작을 확인한다.
  패치 3의 `attempt_sink` 선행은 현재 gateway에서 확인하며 누락 시 일반 코드 적용을 중단한다.
- 호출 기록 API와 패치 자동 적용은 다른 개념이다. 앱·빌드·CI가 자료를 자동 적용하지 않는
  기존 경계는 유지한다. 자료를 병합한 사실은 서비스 기능의 활성화 근거가 아니다.
- 각 일반 코드 적용 PR 작성자가 해당 항목의 선행 head·병합과 `refresh_on` 조건을 재확인한다.
  현황·실행 결과는 이 ADR에 복제하지 않고 관련 구현 기록과 PR에 남긴다.
