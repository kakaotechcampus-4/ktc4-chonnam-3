# 0063 Director 주제 식별자의 생성·저장 경계

상태: 2026-11-11 로컬 실험 개발·평가 채택. [0059](0059-director-request-bound-question-contract.md)의 신규 v17 생성 경계를 보완하며 과거 원문 복원 원칙은 유지한다.

## 맥락

`InterviewTurn.topic_code`는 기존 PostgreSQL `VARCHAR(50)` 필드다. 신규 생성 후보의
주제 식별자가 이 범위를 넘으면 질문 내용과 독립 검토가 유효하더라도 같은 값으로
저장할 수 없다. 모델에 요청하는 형식과 후보 검증을 기존 저장 경계에 맞춘다.

원시 Plan 디코더는 신규 생성뿐 아니라 과거 시도의 감사·복구·평가에도 사용된다.
그 디코더에 새 저장 상한을 적용하면 과거 원문을 현재 생성 규칙으로 다시 거절하거나
재해석할 수 있으므로 생성 경계와 복원 경계를 구분한다.

## 결정

- 신규 v17 source-bound Plan 생성의 `topic_code`는 50자 이하다. 생성 요청 스키마의
  해당 필드에만 `maxLength: 50`을 적용하고 신규 후보의 검증·재검사에서도 확인한다.
  다른 질문 본문·목적·사유 문자열에 이 상한을 전파하지 않는다.
- 상한은 UTF-8 바이트 수가 아닌 문자 수다. Python `len(str)` 및 JSON Schema
  `maxLength`의 Unicode 문자 수를 기준으로 하며 표시 폭이나 사용자에게 보이는
  글자 묶음 수로 세지 않는다. 기존 PostgreSQL 문자 수 제한에 맞춘다.
- 초과한 식별자를 자르거나 정규화해 통과시키지 않는다. 서로 다른 주제를 같은 값으로
  바꾸거나 검토한 질문과 저장한 식별자가 달라지는 일을 막기 위해 원래 후보를 거절한다.
- 공유 Plan 디코더와 과거 원시 시도·질문·진단의 복원 규칙은 유지한다. 신규 생성의
  제약을 과거 기록에 소급하지 않고 원래 문자열을 보존한다.
- 공개 `Question`·REST·WS 계약, 기존 DB 필드와 마이그레이션, Review v3 및 v1~v16의
  생성 규칙은 변경하지 않는다. 이 결정은 신규 v17 producer와 기존 저장소 사이의
  내부 경계다.

## 이유와 영향

기존 저장 필드를 늘리는 대신 그 필드에 들어갈 새 식별자의 길이를 생성 시점부터
제한한다. DB 확장·전역 주제 taxonomy를 새로 요구하지 않고, 단순 절단으로 식별자의
뜻이나 원문을 바꾸지 않는다. 공급자의 스키마 준수 여부와 별개로 후보 검증에서도
같은 범위를 확인하며 기존 Controller의 저장 검사와 권한·복구 상한을 유지한다.

정책의 범위는 [AI 내부 계약](../contracts.md)에 두고, 구현·실행 결과와 남은 검증은
[구현 기록](../implementation.md)에 둔다.
