# 0011 — 저장한 답변을 보존하는 유한 질문 복구

- 상태: Accepted for local implementation
- 날짜: 2026-11-09
- 승인: 사용자 요청 — 네 답변 보존·이어가기 구현, 수정 가능한 거절의 자동 재생성 우선
- 대체 관계: Partially supersedes [공통 0010](0010-in-progress-question-failed-unrecoverable.md)의 다음 질문 복구 금지 범위.
- 공통 계약 검토: FE 검토와 통합 검증 후 병합하며 로컬 승인을 팀 승인으로 간주하지 않는다.
- 관련: 공통 0010의 후속 결정. 팀 검토·PR 게시·운영 배포 승인을 의미하지 않는다.

## 맥락

실제 음성 면접에서 4번 답변까지 저장한 뒤 5번 후보가 독립 검토에서 거절됐다.
질문 문장에는 원인·재발 방지·검증이 있고 계약에는 불일치 회복까지 요구하여 둘이 일치하지 않았다.
반려 후보를 발행하지 않는 검증은 유지해야 하지만, 같은 레포의 새 면접으로 돌아가는
기존 복구만으로는 이미 수행한 질문·답변·분석을 이어갈 수 없다.

## 결정

1. 최초 Director Plan 1회와 독립 Review 1회를 유지한다.
2. 안전한 대안이 있는 `director_candidate_rewrite` 반려는 서버에서 자동 1라운드 복구한다.
   이전 후보·반려 사유는 새 Plan의 비권위적 참고자료이며 원문·사실·허용 근거로 승격하지 않는다.
   새 후보는 새 독립 Review를 통과해야 한다.
3. 자동 복구가 끝난 뒤에도 실패하면 사용자가 명시적으로 다음 질문 이어가기를 1회 요청할 수 있다.
   라운드당 Plan 1회+Review 1회, 질문 하나당 최초·자동·수동을 합쳐 최대 6회다.
   알려진 오류라고 무제한 반복하거나 검토를 생략하지 않는다.
4. 동일 면접 ID·기존 질문/답변/분석/근거·선택 SHA와 과거 실패 기록은 보존한다.
   STT·T3·L1/L2·이미 확정한 답변을 다시 실행하거나 새 면접으로 복사하지 않는다.
5. `POST /interviews/{id}/question/retry`는 UUID `requestId`를 받고,
   성공 시 `{interviewId,sessionId,turnNo}`를 200으로 반환한다. 새 realtime sessionId로 재접속한다.
   동일 요청 ID는 그 요청의 성공·실패를 재생하며 새 턴을 추정해 모델을 다시 부르지 않는다. 현재 미답변 대상 턴에만 realtime 세션을 교체하며 과거 성공 요청은 현재 연결을 바꾸지 않는다.
6. GET detail의 선택 필드 `canRetryQuestion`·`questionRetryCount`로 이어가기 가능 여부와
   수동 횟수를 표시한다. 기본값은 false·0이다. 선택 nullable `questionRetryState`는 requestId·turnNo·status(running/succeeded/failed)·expiresAt을 제공하며 새로고침 때 같은 요청을 복원한다. 완료·중단·다른 소유자·T3 실패는 대상이 아니다.
7. DB row lock과 별도 유한 복구 원장으로 대상 턴·기존 답변/분석·실패 호출·새 호출·요청 ID·
   실행 기한·결과를 연결한다. 동시 요청은 중복 실행하지 않고 기한/상태 변경 뒤 결과는 폐기한다.
   모델 성공 후 Redis 응답 발급이 실패해도 이미 저장한 질문을 재생하며 합성하지 않는다.
8. 종료된 자동/수동 복구까지 실패하면 `question_failed`의 recoverable=false와 기존 기록 보존을 유지한다.
   재접속·동일 답변 재전송만으로 무한 모델 재실행을 시작하지 않는다.

## 이유와 영향

수정 가능한 질문 불일치는 사용자 응답을 잃지 않고 내부에서 먼저 해결한다.
고정 질문 대체나 심사 완화 없이 검토·비용·중복 실행의 경계를 유지한다.
명시 수동 이어가기는 자동 복구의 한도를 무제한 늘리는 권한이 아니다.

FE에는 저장 답변으로 이어받기와 요청 중 중복 행동 차단이 추가되고,
BE에는 소유권·상태·요청 재생과 다음 질문 저장 경계가 추가된다.
AI에는 v6를 보존한 v7 피드백 해석과 동일한 턴 의미·실제 ID 보호가 필요하다.
원장의 물리 저장은 기존 context_state를 사용하며 새 업무 테이블이나 마이그레이션을 요구하지 않는다.

## 대체 관계

공통 0010의 T4 반려 시 즉시 전체 재시작만 제공하던 범위를 이번 자동/명시 복구로 구체화한다.
T3 실패, 인증·영구 공급자 오류와 복구 상한 이후에는 기존 중단·안내 경계를 유지한다.
공통 0010 원문과 기존 실패 이력은 변경하지 않는다.
실제 구현·실행 결과는 `spec/ai/implementation.md`에 기록한다.

화면은 HTTP 성공 후 새 질문을 30초 안에 받지 못하면 같은 UUID의 결과 재확인과 나가기를 제공한다. 인증·quota 등 영구 오류는 복구 가능 상태로 노출하거나 수동 횟수를 소비하지 않는다. 최초 조회 요약·Tool 결과를 그대로 복원하며 추가 조회나 T3·L2 재실행을 하지 않는다.
