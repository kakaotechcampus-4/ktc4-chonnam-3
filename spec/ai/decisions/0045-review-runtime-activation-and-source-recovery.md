# 0045. 리뷰 후 실행 활성화와 원문 복구 경계

- 상태: Accepted for development, 2026-11-09
- 관련 PR: #212, #213, #216, #217, #218
- 구현·검증 기록: [단일 구현 기록](../implementation.md#review-followups-20261109)

## 결정

1. 프롬프트 파일 생성과 DB 활성화를 구분한다. 실제 설치된 소비자가 선언한 지원 버전으로 전체 목록을 검사한 뒤 한 트랜잭션으로 활성화한다. 배포 접미사는 감사·캐시·저장에서 보존하고 지원 여부를 확인할 때만 기본 버전을 사용한다. 소비자 미설치·출력 계약 불일치는 활성화 전에 거절한다.
2. 준비와 리포트 작업에만 1800초 ARQ 제한을 둔다. 다른 작업의 기본 제한은 600초로 유지한다. 준비 내부 마감은 1770초이며 문서·레포·대조·Director 호출별 시간을 명시해 합산 검사한다. 구형 두 인자 호출은 당시 L2·Director의 6T 계약을 보존하며, 문서·Claim을 실행하는 신규 호출자는 세 작업 예산을 함께 전달한다. 수치는 현재 실행 정책이며 공급자 지연이나 품질의 보장이 아니다.
3. 개발 모델·최대 출력·추론 강도·선택 음성 예산은 별도 선택 프로필로 둔다. 공통 예제가 모든 배포의 개인 운영 설정을 강제하지 않는다. 실제 로컬 비밀 설정과 이미 등록된 DB 프롬프트는 자동 변경하지 않는다.
4. 원문 좌표는 추출 블록과 동일한 줄 나누기 규칙으로 계산한다. 과거 좌표 규칙이 불분명하면 페이지·좌표를 추측하지 않는다. Claim 실행에는 만료·실행권을 두고 늦은 이전 결과가 새 성공을 덮지 못하게 한다.
5. 완전한 텍스트 PDF는 native 추출을 우선한다. 명시적 레이아웃 보완 선택, 읽지 못한 페이지, 이미지·스캔 입력에 Vision을 적용한다. 전사와 생성 해석은 별도로 유지한다.
6. 이미지 공고의 실패·부분 추출 결과는 텍스트 결과와 함께 이용할 수 있지만 일반 7일 캐시로 확정하지 않는다. 60초 재사용 창 이후 새 요청에서 보완을 재시도한다. 원문·요구사항·추출 건강 상태가 달라지면 새 자료로 보존해 과거 면접의 참조를 바꾸지 않는다. 이 간격은 연타 방지 정책이며 자동 무한 재시도가 아니다.
7. 검색 질의는 새 모델 출력·Tool·직접 공급자 경계에서 공통 정책으로 검사한다. 위험 질의가 섞이면 전체 batch를 외부 호출·신규 저장 전에 거절한다. 과거 계약 복원·저장 원문은 바꾸지 않는다. 휴대전화 등 명확한 패턴 검사는 모든 개인정보 탐지를 보장하지 않는다.
8. TTS 오디오 확보 후 정산·캐시는 각각 유한 시간 보호한다. 정산 장애 때문에 이미 받은 오디오를 버리지 않으며, 사용 예산을 환불하거나 Redis epoch를 임의 재초기화하지 않는다. 호출자 취소는 마무리 후 전파한다.
9. 프로필 outbox 생산자와 3인수 worker·reaper·모델·마이그레이션은 같은 적용 묶음이다. 선행이 빠진 공개 활성 경로는 기존 user-only 전달을 유지하고 신규 연결·검증은 비활성 후속 패치로 보존한다.
10. 리포트 점수 턴에는 그 질문이 연결한 JD만 전달한다. 전체 JD·원문 출처·미확인 범위는 리포트 입력의 별도 필드로 유지한다. 존재하지 않는 연결 ID는 조용히 버리지 않는다. 읽기 전용 조회는 생성 예약의 잠금과 분리하고 모델 미호출 종료도 영속 요청 상태에 남긴다.

## 게시·검증 조건

- 공개 REST 계약은 OpenAPI와 대응 설명을 함께 적용한다. 선행 명세가 미병합이면 양쪽 변경을 같은 비활성 묶음으로 유지한다. WebSocket `error.details`는 기존 계약의 선택 객체로 설명한다.
- 기존 PR 번호와 원본 실행본을 보존한다. 수정한 원본 PR 뒤의 후속 패치도 실제 적용 전·후 지문으로 다시 확인한다.
- 통합 검증과 각 게시본의 단독 검증을 구분한다. 외부 공급자 비용·실서비스 품질·사람 검수 완료를 자동 테스트 통과로 대체하지 않는다.
